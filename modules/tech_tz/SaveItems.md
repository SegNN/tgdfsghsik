# Техническое задание — модуль SaveItems

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/SaveItems`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | SaveItems |
| Артефакт (Maven) | `SaveItems` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0 |
| Главный класс | `ru.extas7y.saveitems.SaveItems` |
| API-версия Bukkit | 1.16 |
| Авторы (plugin.yml) | Extas7y |

**Назначение:** база именованных предметов для сервера. Администратор сохраняет
в БД предмет из руки под именем с ценой (в «сапфирах» — валюте PlayerPoints),
после чего предмет можно выдавать игрокам или продавать через GUI подтверждения
покупки со списанием сапфиров. Используется как справочник предметов для магазина.

---

## 2. Окружение и зависимости

## 3. Архитектура (структура пакетов)

```
ru.extas7y.saveitems
├── SaveItems               — главный класс: init БД, регистрация команды/листенера,
│                             утилита addItemInventory (умная укладка предмета в инвентарь)
├── command.CommandHandler  — роутер подкоманд /saveitems
├── command.ISubCommand     — интерфейс подкоманды (Argument() + execute())
├── command.args.Add        — сохранить предмет из руки в БД
├── command.args.Remove     — удалить предмет из БД
├── command.args.List       — список предметов с ценами
├── command.args.Give       — выдать предмет игроку
├── command.args.Buy        — открыть игроку GUI подтверждения покупки
├── database.MyDatabase     — SQLite/MySQL, CRUD таблицы saved_items, сериализация ItemStack (BukkitObjectOutputStream)
└── object.SaveItemsObject  — GUI покупки (27 слотов) + обработчик кликов (Listener)
```

## 4. Функциональные требования

### 4.1. Команда `/saveitems` (алиас `/si`)
Права в plugin.yml не заданы — команда доступна всем (включая игроков). Ошибка
«Unknown command. Please try /help» от Bukkit при возврате `false` (используется
для не-игроков в add/remove/list).

| Подкоманда | Синтаксис | Поведение |
|---|---|---|
| `add` | `/si add <имя> <цена>` | Берёт предмет из главной руки игрока и сохраняет в БД (имя, BLOB предмета, цена — double). Сообщения: «Цена должна быть числом!», «Вы должны держать предмет в руке.», «Предмет добавлен в базу данных.» |
| `remove` | `/si remove <имя>` | Удаляет запись. «Предмет удален из базы данных.» |
| `list` | `/si list` | Отправляет «Список предметов:» + строки «имя - цена» по всем записям |
| `give` | `/si give <игрок> <имя> <кол-во>` | Выдаёт онлайн-игроку предмет из БД в количестве N (звук `ENTITY_PLAYER_LEVELUP`). Сообщения: «Количество должно быть числом!», «Игрок не найден.», «Предмет не найден.» |
| `buy` | `/si buy <игрок> <имя> <кол-во> <команда…>` | Открывает игроку GUI покупки (см. 4.2). Хвостовые аргументы (с 5-го) склеиваются в команду возврата. Ошибки (мало аргументов, нечисловое кол-во, игрок офлайн, предмет не найден) завершаются молча |
| (без аргументов) | `/si` | «Используйте подкоманду: add, remove, list, give, buy» |
| (неизвестная) | | «Неизвестная подкоманда. Доступные: add, remove, list, give, buy» |

### 4.2. GUI подтверждения покупки (`SaveItemsObject.display`)
- Инвентарь 27 слотов, заголовок: `Покупка предмета` + ~250 пробелов + маркер
  `[saveditems:buy]` (по заголовку определяется кликами).
- Раскладка: слоты 0,1,2,9,10,11,18,19,20 — зелёные панели «Купить»
  (`LIME_STAINED_GLASS_PANE`); 6,7,8,15,16,17,24,25,26 — красные «Отменить покупку»
  (`RED_STAINED_GLASS_PANE`); 3,4,5,12,14,21,22,23 — голубые пустые панели;
  слот 13 — сам предмет, в лор которого добавляются строки:
  «▍Вы уверены что хотите подтвердить покупку предмета?» и «▍Цена: <цена> сапфиров ☀».
- В PDC (PersistentDataContainer) предметов меню записываются ключи:
  `buyitem` (`confirm`/`cancel`/`other`/`item`), `itemId`, `command`, `price` (DOUBLE).
- Все клики в меню отменяются.
- **Клик «Отменить»** — консоль выполняет сохранённую команду возврата
  (по умолчанию `am open shop %player_name%`) с подстановкой PlaceholderAPI.
- **Клик «Купить»**:
  1. Баланс сапфиров читается как `Double.parseDouble(PlaceholderAPI.setPlaceholders(player, "%playerpoints_points%"))`.
  2. Если баланс ≥ цены: звук `ENTITY_ENDER_EYE_DEATH`, консольная команда
     `p take <ник> <целая часть цены>` (списание PlayerPoints), выдача предмета
     (через `addItemInventory`), затем команда возврата.
  3. Иначе: сообщение «У вас недостаточно сапфиров. Приобрести сапфиры можно на
     сайте - ExampleWorld.su» и команда возврата.
- Цена покупки = `getPrice(имя) × количество` (double; списывается `.intValue()`).

### 4.3. Укладка предмета в инвентарь (`SaveItems.addItemInventory`)
- Перебираются слоты хранения: если слот пуст — предмет кладётся целиком;
  если совпадает по `isSimilar` — досыпается до `maxStackSize`, остаток переносится дальше.
- Если инвентарь полон — предмет выпадает на землю у игрока
  (`dropItemNaturally` в главном потоке).

## 6. Хранение данных

Таблица `saved_items` (создаётся автоматически):
- MySQL: `id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(255) UNIQUE NOT NULL, item_data LONGBLOB NOT NULL, price DOUBLE NOT NULL`
- SQLite: `id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT UNIQUE NOT NULL, item_data BLOB NOT NULL, price REAL NOT NULL`

- SQLite-файл: `<dataFolder>/data.db`; MySQL-URL:
  `jdbc:mysql://<host>/<db>?autoReconnect=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC`.
- Одно «сырое» JDBC-соединение (`DriverManager`, без пула); при каждом запросе
  проверяется живость и переподключается (`checkConnection`).
- `ItemStack` сериализуется в байты `BukkitObjectOutputStream`/`BukkitObjectInputStream`.
- Все запросы выполняются синхронно в главном потоке.

## 7. Интеграции
- **PlaceholderAPI** — плейсхолдеры `%playerpoints_points%` (баланс сапфиров) и
  `%player_name%` (в команде возврата).
- **PlayerPoints** — списание командой `p take` от имени консоли.
- Команда возврата по умолчанию `am open shop %player_name%` (внешний плагин магазина).

---

## 8. Сценарий работы
1. `/si add <имя> <цена>` с предметом в руке — предмет сохранён в БД.
2. Внешний контекст (магазин/команда) вызывает `/si buy <игрок> <имя> <кол-во> <команда>`.
3. Игроку открывается GUI: предмет по центру с ценой, «Купить» слева, «Отменить» справа.
4. «Купить»: проверка баланса PlayerPoints → списание `p take` → выдача предмета
   (или дроп при полном инвентаре) → возврат в магазин командой.
5. «Отменить»: сразу возврат в магазин.

## 9. Особенности реализации и известные ограничения
- Права не предусмотрены вообще: `add`/`remove`/`give` доступны любому игроку,
  знающему синтаксис (ограничение безопасности).
- `buy` не проверяет, что отправитель — игрок; выполняется для любого отправителя.
- Все сообщения жёстко зашиты в код.
- Клики обрабатываются по строке-заголовку инвентаря; при `getCurrentItem()` равном
  null/AIR будет NPE (слоты «other» защищены PDC, но клик по пустому слоту 13-му соседнему
  вне раскладки невозможен — все 27 слотов заняты).
- Работа с БД синхронная, без пула — при MySQL возможны лаги главного потока.
- Повторный `add` с тем же именем падает по UNIQUE-ограничению (stacktrace в лог,
  сообщение об ошибке игроку не выводится).
- `getPrice` возвращает −1 при отсутствии записи (используется как «не найдено»).
