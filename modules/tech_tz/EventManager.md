# Техническое задание — модуль EventManager

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/EventManager`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | EventManager |
| Артефакт (Maven) | `EventManager` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT |
| Главный класс | `org.dimasik.eventmanager.EventManager` |
| API-версия Bukkit | 1.16 |
| Авторы (plugin.yml) | не указаны |

**Назначение:** ядро системы серверных ивентов. Планирует и проводит **периодические
голосования игроков за следующий ивент**, ведёт обратный отсчёт до следующего голосования,
показывает актуальную информацию об ивентах по команде `/event` и предоставляет другим
Event-плагинам общий реестр активных ивентов — публичное поле
`EventManager.instance.events: HashMap<String, Event>` (ключ — строковый идентификатор
ивента, значение — `Event { name, message }`). Под-ивенты (EventContainer, EventDeathMine,
EventGruz, EventPolana и др.) кладут туда свои статусы-строки, а EventManager выводит их
всем игрокам по `/event`.

---

## 2. Требования к окружению и зависимости

### 2.1. Сервер
- Paper/Spigot (API 1.16+; фактически собирается против `io.papermc.paper:paper-api:1.21.4-R0.1-SNAPSHOT` из родительского pom, Java 21 — `maven.compiler.release=21`).
- Плагин сам по себе ни от каких других плагинов не зависит (`plugin.yml` без `depend`/`softdepend`); зависимости появляются у под-ивентов, которые используют его API.

### 2.2. Библиотеки
- `org.jetbrains:annotations:24.1.0` (provided) — только для аннотаций, ни на что не влияет.

### 2.3. Связь с другими модулями (потребители API)
По коду репозитория реестр `events` и `EventManager.getInstance()` используются модулями:
EventContainer (ключ `container` и `wait_event`-слоты не использует, только `container`),
EventDeathMine (ключ `death_mine`), EventGruz (ключ `gruz`), EventPolana (ключ `polana`),
а также прочими под-ивентами (ship, posilka, zamok и т.д. — судя по конфигу голосования).
Сам EventManager по завершении голосования кладёт в реестр временный ключ `wait_event`.

## 3. Архитектура (структура пакетов)

```
org.dimasik.eventmanager
├── EventManager      — главный класс: singleton (instance), таймер до голосования,
│                       реестр events, команда /event (делегирует EventCommand),
│                       регистрация EventVote (листенер + /vote), sendEventMessage()
├── Event             — публичная POJO-запись об ивенте: name (displayName) и message (строка для /event)
├── EventVote         — вся логика голосования: загрузка ивентов из config.yml, случайный
│                       выбор 3–4 кандидатов, GUI-меню голосования с живым таймером,
│                       подсчёт голосов, определение победителя, отложенный запуск команды
│                       победившего ивента от имени консоли; CommandExecutor для /vote
│                       и Listener кликов в меню; внутренний класс EventVote.Event
│                       (material, displayName, lore, glow, commands, name, счётчик vote)
├── EventCommand      — исполнитель команды /event: инфо-сообщение игроку или
│                       /event settimer <секунды> для админов (право eventmanager.admin)
└── EventMenyHolder   — пустая реализация InventoryHolder-маркера, по которой
                        опознаётся меню голосования в InventoryClickEvent
```

## 4. Функциональные требования

### 4.1. Цикл голосования (автоматический)
1. При `onEnable` читается `timer` из config.yml (минуты), поле `timer` плагина = `timer * 60` секунд (при стандартном конфиге — 1800 с).
2. Запускается задача `updateTimerTask()` — тик раз в секунду (20 тиков): уменьшает `timer` на 1; при `timer <= 0` — сброс `timer` из конфига и вызов `EventVote.startVoting()`.
3. `startVoting()`:
   - `isVoting = true`, `votingTimeLeft = 120` (2 минуты, константа);
   - всем онлайн-игрокам рассылается объявление («Запущено голосование за следующее мероприятие.» / «Прописывай /vote…») и звук `BLOCK_BEACON_ACTIVATE`;
   - `loadEvents()` перечитывает секцию `items` конфига;
   - `fillEvents()` выбирает случайных кандидатов (см. 4.2);
   - создаётся меню голосования; запускаются две задачи: посекундное обновление меню
     (`votingTimeLeft--`, `updateVoteMenu()`) и `finishVoting()` через 2400 тиков (120 с).
4. `finishVoting()`:
   - `isVoting = false`, все задачи отменяются, меню закрывается у всех зрителей;
   - подсчёт: у каждого кандидата поле `vote`; победитель — `max` по значению
     (при равенстве — произвольный, порядок HashMap; при полном отсутствии голосов
     побеждает случайный из кандидатов);
   - формируется broadcast-сообщение (см. 4.4) и рассылается в чат;
   - в реестр `plugin.events` кладётся ключ `wait_event` (строка-объявление), чтобы
     `/event` показывал «скоро появится»;
   - через 1200 тиков (60 с) ключ `wait_event` удаляется и **консолью** выполняется
     одна случайная команда из списка `commands` победившего ивента
     (`Bukkit.dispatchCommand(console, command)`) — именно так стартует под-ивент.
5. `stopVoting()` (ручная остановка): `isVoting = false`, голоса сбрасываются, задачи отменяются, меню закрывается. Никакие команды ивентов не выполняются.

### 4.2. Выбор кандидатов голосования (`fillEvents`)
- Всего в конфиге должно быть **минимум 2 ивента**, иначе `IllegalStateException` («Недостаточно событий…»).
- Ключи перемешиваются (`Collections.shuffle`); количество кандидатов = `min(random.nextInt(3) + 3, min(4, всего))`, т.е. **3 или 4 случайных ивента**.
- Голоса (`playerVotes`) очищаются перед каждым голосованием.

### 4.3. Меню голосования (GUI)
- Инвентарь 27 слотов, заголовок `Голосование [M мин, S сек.]` (пересоздаётся каждую секунду для обновления таймера в заголовке; открытые меню переоткрываются у всех зрителей).
- Слоты размещения: 2 кандидата — начиная со слота 12, 3 — с 11, иначе с 10; шаг между предметами 2 слота.
- Предмет кандидата: `Material` из `material` (невалидное имя — лог в консоль, предмет пропускается), имя из `displayname`, лор из `lore` с заменой плейсхолдера `%amount%` на текущее число голосов, зачарование-«свечение» при `glow: true` (LUCK_OF_THE_SEA 1 + HIDE_ENCHANTS).
- В PDC предмета пишется ключ `event-name` (NamespacedKey `eventmanager:event-name`) — идентификатор кандидата.
- Клик по предмету: событие отменяется; повторный голос переводится (у старого кандидата `vote--`, у нового `vote++`; в `playerVotes` хранится UUID → id кандидата). Клик по пустым слотам игнорируется.

### 4.4. Сообщения о победителе
Цвет заголовка извлекается из первых 14 символов `displayname` (HEX-префикс `&x&…`); если префикс не HEX — цвет по умолчанию `&x&F&F&B&C&3&B`. Тексты и звуки зависят от `name` победившего ивента:

| name (config `items.<key>.name`) | Текст объявления | Звук всем игрокам |
|---|---|---|
| `deathmine`, `svetpolana`, `container`, `posilka`, `gruz`, `ship`, прочие (default) | «…появится через минуту на рандомных координатах.» | — (posilka: `ENTITY_PLAYER_BREATH`; gruz: `ENTITY_VILLAGER_WORK_FARMER`; ship: `ENTITY_VILLAGER_AMBIENT`; default: `AMBIENT_SOUL_SAND_VALLEY_ADDITIONS`) |
| `boss` | «…появится через минуту на пвп арене (/warp pvp).» | `BLOCK_BELL_USE` |
| `zamokgoldrush` | «…начнется на координатах 0 63 0 уже через минуту.» | `ENTITY_SHULKER_BULLET_HURT` |
| `tipo ` (с пробелом) | «…появится через минуту на рандомных координатах.» | `ENTITY_EXPERIENCE_BOTTLE_THROW` |

Формат: `цвет ▶ <displayname> &f <хвост>`, рассылается в общий чат (`Bukkit.broadcastMessage`) с пустыми строками до и после.

### 4.5. Информация по `/event` (`sendEventMessage`)
- Идёт голосование → строки «Запущено голосование…».
- Голосования нет, реестр `events` пуст → «Ближайшее голосование за мероприятие будет проводиться через N мин., S сек.».
- Голосования нет, реестр непуст → выводится `message` каждой записи реестра (статусы активных ивентов от под-плагинов и `wait_event`).

### 4.6. Команды

**`/vote`** (исполнитель `EventVote`; алиасов нет; права в plugin.yml не объявлены):
| Синтаксис | Право | Поведение |
|---|---|---|
| `/vote` | — | Если голосование идёт — открыть меню; иначе сообщение «В настоящее время голосование не проводится.» |
| `/vote start` | `mantivote.admin` | Принудительно запустить голосование (ответ «Голосование начато.») |
| `/vote stop` | `mantivote.admin` | Остановить без подведения итогов («Голосование остановлено.») |
| `/vote finish` | `mantivote.admin` | Немедленно завершить с подведением итогов и запуском ивента («Голосование завершено.») |
| `/vote start/stop/finish` без права | — | Игроку открывается меню (как у `/vote`) |

**`/event`** (исполнитель `EventCommand`):
| Синтаксис | Право | Поведение |
|---|---|---|
| `/event` | — | Игроку — `sendEventMessage` (см. 4.5); консоли — справка |
| `/event settimer <число>` | `eventmanager.admin` | Установить таймер до следующего голосования в **секундах** (`setTimer`), сохранить значение в config.yml `timer`, ответ «Время до следующего голосования задано на N сек.» |
| `/event <иное> <число>` | `eventmanager.admin` | Первый аргумент фактически не проверяется: любой второй аргумент-число трактуется как новое время (поддерживается только сценарий `settimer`) |
| некорректное число | — | Сообщение «Использование: /event settimer [новое время]» |

### 4.7. Права (permissions)
В `plugin.yml` права не объявлены. Проверяются в коде:
| Право | Где | Назначение |
|---|---|---|
| `mantivote.admin` | `EventVote.onCommand` | `/vote start` / `/vote stop` / `/vote finish` |
| `eventmanager.admin` | `EventCommand.onCommand` | `/event settimer` (при отсутствии — игрок получает только инфо-сообщение) |

### 4.8. Обрабатываемые события
- `InventoryClickEvent` (EventVote) — клики в меню голосования (распознавание по `EventMenyHolder`).
- Команды `/vote`, `/event` (через plugin.yml).

### 4.9. Плейсхолдеры в конфиге
| Плейсхолдер | Где | Значение |
|---|---|---|
| `%amount%` | `items.<key>.lore` | Текущее количество голосов за ивента (обновляется в меню каждый тик-обновления) |

Цвета: `ChatColor.translateAlternateColorCodes('&', …)` — поддерживаются коды `&x&F&8&6&D…` (HEX) и обычные `&c`, `&l` и т.д.

## 5. Конфигурация (config.yml, единственный файл)

| Параметр | Тип | Default (в поставке) | Описание |
|---|---|---|---|
| `timer` | int | 30 | Период между голосованиями, **минуты** (умножается на 60). После `/event settimer N` в файл пишется N как есть (см. §9) |
| `items` | секция | 8 ивентов | Кандидаты голосования |
| `items.<key>` | string | `gruz`, `ship`, `posilka`, `boss`, `container`, `zamokgoldrush`, `deathmine`, `svetpolana` | Идентификатор (он же значение PDC `event-name` в меню) |
| `items.<key>.name` | string | = key | Внутреннее имя ивента для switch-сообщений победителя (4.4) |
| `items.<key>.material` | string | `chest`, `tripwire_hook`, `ender_chest`, `respawn_anchor`, `blue_shulker_box`, `gold_block`, `netherite_pickaxe`, `oxeye_daisy` | Материал иконки в меню (Material.valueOf, верхний регистр) |
| `items.<key>.displayname` | string | HEX-строки | Отображаемое имя («Уникальный груз», «Танствующий корабль» [как в коде опечатка оригинала], «Посылка», «Мистический босс», «Контейнер», «Золотая лихорадка», «Смертельная шахта», «Цветочная поляна») |
| `items.<key>.lore` | list[string] | HEX-строки | Лор иконки; описание ивента + строка «Нажмите, чтобы проголосовать ЗА (%amount% голосов)» |
| `items.<key>.glow` | boolean | false | Свечение иконки (зачарование + скрытие) |
| `items.<key>.commands` | list[string] | см. ниже | Пул команд; одна случайная выполняется консолью через 60 с после победы |

Команды в поставке (запускают под-ивенты):
- gruz: `gruz spawn peaceful`, `gruz spawn explosive`, `gruz spawn death`
- ship: `ship spawn`
- posilka: `posilka spawn default`, `posilka spawn epic`, `posilka spawn legendary`
- boss: `boss spawn`
- container: `econtainer spawn default`, `econtainer spawn epic`
- zamokgoldrush: `zamok goldrush start`
- deathmine: `deathmine spawn`
- svetpolana: `polana spawn`

`reloadConfig()` плагином не вызывается; конфиг перечитывается только при рестарте (и посекундно `items` не перечитывается — только `loadEvents()` на старте каждого голосования).

## 6. Хранение данных
- Постоянное хранение — только `config.yml` (значение `timer`, редактируемое `/event settimer`).
- Состояние в памяти: `EventManager.events` (реестр активных ивентов), `EventVote.playerVotes` (UUID → выбор), счётчики `vote`, меню. Всё теряется при перезапуске; голосование не восстанавливается.

---

## 7. Интеграции
- **Нет** интеграций с PlaceholderAPI, Vault и т.п. — код их не использует.
- Интеграция с под-ивентами — через общий classloader-сервер: под-плагины берут `EventManager.getInstance()` и кладут/удаляют записи в `events`; EventManager не знает о них ничего, кроме `commands` из конфига.

---

## 8. Сценарий работы (основной поток)
1. (Тик) Таймер `timer` уменьшается каждую секунду; достигнув 0 — `startVoting()`.
2. Из config.yml загружаются все ивенты; случайно выбираются 3–4 кандидата; создаётся меню.
3. Игроки вводят `/vote`, кликают по иконке (голос можно менять — старый снимается).
4. Каждую секунду обновляются заголовок меню и счётчики `%amount%`.
5. Через 120 с — `finishVoting()`: меню закрыто, определён победитель (максимум голосов).
6. Broadcast-анонс победителя (текст/звук по `name`), в реестр кладётся `wait_event`.
7. Через 60 с: `wait_event` удалён, консоль выполняет случайную команду из `commands` победителя (например `gruz spawn death`) — стартует соответствующий под-ивент, который сам зарегистрирует свой статус в `EventManager.events`.
8. Дальше по `/event` игроки видят статусы активных ивентов до их завершения (под-ивент сам удаляет свою запись).
9. `timer` продолжает цикл — следующее голосование через `timer` минут.

## 9. Особенности реализации и известные ограничения
- **Права не объявлены в plugin.yml** (`mantivote.admin`, `eventmanager.admin` работают только при ручном выставлении/perm-плагине; default — op через стандартную семантику hasPermission отсутствующего права = только op).
- `setTimer()` не отменяет предыдущую задачу таймера: после `/event settimer` работает **две** секундные задачи одновременно (таймер тикает вдвое быстрее). Также `timer` в конфиге трактуется как минуты (×60), а `/event settimer N` пишет N в конфиг как есть — после рестарта значение интерпретируется заново как минуты.
- Меню голосования пересоздаётся целиком каждую секунду (для таймера в заголовке) — все зрители переоткрывают инвентарь; возможен мигающий курсор/сдвиг выделения слота.
- При равенстве голосов победитель выбирается произвольно (порядок обхода HashMap); при нуле голосов побеждает случайный кандидат и его команда всё равно запускается.
- Ветка `name == "tipo "` (с завершающим пробелом) недостижима при корректном конфиге.
- Некорректный `material` кандидата логируется и кандидат пропускается без предупреждения игрокам.
- `EventVote.onCommand` в ветке «без права» кастует sender к Player — для неигрового отправителя без права возможен ClassCastException.
- Длительность голосования (120 с) и задержка запуска (60 с) захардкожены (2400 и 1200 тиков).

## 10. Сборка
```
mvn -pl modules/EventManager -am package   # из корня репозитория (FichaWorld-src)
```
Модуль входит в reactor корневого `pom.xml`; специфичных плагинов сборки нет
(shade не используется, jar без зависимостей — всё внешнее provided).
