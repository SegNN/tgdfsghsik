# Техническое задание — модуль Expirytime

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/Expirytime`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | Expirytime |
| Артефакт (Maven) | `Expirytime` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT (версия экспансии — «1.0») |
| Главный класс | `org.dimasik.expirytime.Expirytime` |
| API-версия Bukkit | 1.16 |
| Автор (в экспансии) | Dimasik |

**Назначение:** мини-плагин-провайдер одного плейсхолдера PlaceholderAPI,
показывающего время до окончания донат-привилегии игрока. Источник данных —
группа LuckPerms (первичная группа игрока) и срок её `InheritanceNode`.
Формат вывода — «∞» для бессрочных, `Nд` для сроков от суток (с округлением
вверх), иначе `Чч Мм`; при невозможности определить — «Ошибка».

Команд, событий, конфигурации и хранилищ нет.

---

## 2. Требования к окружению и зависимости

| Зависимость | Версия | Scope | Назначение |
|---|---|---|---|
| PlaceholderAPI | 2.12.3 | provided (`local.plugins:placeholderapi`) | регистрация экспансии `expire` |
| LuckPerms | 5.5.53 | provided (`local.plugins:luckperms`) | чтение узла первичной группы и его expiry |

- PlaceholderAPI обязателен: при его отсутствии плагин логирует warning
  «PlaceholderAPI не найден! Плагин не будет работать.» и не регистрирует экспансию.
- LuckPerms обязателен: инстанс берётся из `ServicesManager`; если LuckPerms не
  зарегистрирован, поле `luckPerms` остаётся `null` → NPE при запросе плейсхолдера.
- Сервер: Paper/Spigot API 1.16 (сборка Java 21).

## 4. Функциональные требования

### 4.1. Плейсхолдер (PlaceholderAPI, идентификатор `expire`)

| Плейсхолдер | Возвращаемое значение |
|---|---|
| `%expire_donate%` | остаток срока первичной донат-группы игрока (см. алгоритм) |
| любой другой | `null` (плейсхолдер не найден); при `player == null` — `""` |

Алгоритм:
1. `User user = luckPerms.getUserManager().getUser(uuid)`; `null` → `Ошибка`.
2. Среди `user.getNodes()` ищется первый `InheritanceNode`, чьё имя группы равно
   `user.getPrimaryGroup()` (без учёта регистра). Не найден → `Ошибка`.
3. `node.getExpiry()`:
   - `null` (бессрочная группа) → `∞`;
   - иначе `Duration` от «сейчас» до expiry:
     - если полных суток ≥ 1 → `(days + 1) + "д"` — округление вверх («до завтрашнего дня»);
     - иначе → `String.format("%dч %dм", hours, minutes)` где `hours = duration.toHours() % 24`,
       `minutes = duration.toMinutes() % 60`.

### 4.2. Права, команды, события
- Команд нет; события не обрабатываются; права не проверяются
  (плейсхолдер доступен любому контексту PAPI от имени игрока).

## 8. Сценарий работы
1. Старт сервера → LuckPerms берётся из ServicesManager; при наличии PAPI
   регистрируется экспансия `expire`.
2. Игрок с донатом заходит; в меню/табе/чате какой-либо плагин запрашивает
   `%expire_donate%`.
3. Экспансия находит узел наследования первичной группы игрока.
4. Группа бессрочная → «∞»; срок есть → «7д» либо «5ч 30м».
5. По истечении срока LuckPerms сам снимает группу; до снятия плейсхолдер
   показывает остаток, в том числе отрицательный (см. §9).

---

## 9. Особенности реализации и известные ограничения
- `luckPerms` может быть `null` (LuckPerms не зарегистрирован в ServicesManager,
  но PAPI есть) → NPE внутри запроса плейсхолдера, а не при старте.
- Просроченный, но ещё не удалённый узел: `Duration` отрицательный, `days < 1` →
  будет выведено отрицательное время (например `-2ч -15м`) — кейс не обработан.
- Берётся **первый** подходящий InheritanceNode первичной группы: если узлов
  несколько (продления выдавались отдельными узлами), показывается срок
  произвольного (первого в потоке) из них, а не максимальный.
- `user.getPrimaryGroup()` берётся без explicit load — опирается на загруженного
  в кэш пользователя (для онлайн-игрока корректно).
- Расширение не делает `persist()`: после перезагрузки PAPI экспансия жива, пока
  жив плагин (unregister при выключении плагина не вызывается — только при disable
  сервера; `onDisable` пуст).
