# Техническое задание — модуль HolyFreeze

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/HolyFreeze`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | HolyFreeze |
| Артефакт (Maven) | `HolyFreeze` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT |
| Главный класс | `org.dimasik.holyfreeze.HolyFreeze` |
| API-версия Bukkit | 1.16 |
| Авторы | не указаны в plugin.yml; автор PAPI-экспансии — `Dimasik` |

**Назначение:** плагин «заморозки» игроков для античит-проверок на сервере.
Приводит в неподвижность игрока, подозреваемого в использовании читов: блокирует
движение, урон, инвентарь, команды; телепортирует его на площадку проверки
(координаты из конфига), рассылает ему периодические инструкции о прохождении
проверки через AnyDesk (сообщения в чат + Title), а после разморозки возвращает
обратно. Дополнительно реализует статусы персонала (AFK / «На проверке»)
с отображением Title и PlaceholderAPI-плейсхолдером, а также (опционально)
блокировку входа замороженного игрока на другие серверы сети через общую MySQL-БД.

---

## 2. Окружение и зависимости

### 2.1. Сервер
- Paper (обязателен: используется событие `com.destroystokyo.paper.event.player.PlayerJumpEvent`),
  API 1.16+.

### 2.2. Плагины
| Плагин | Тип зависимости | Область применения |
|---|---|---|
| PlaceholderAPI 2.12.3 | depend (обязателен) | Экспансия `holyfreeze` (статусы персонала) |
| Multiverse-Core | softdepend | Только порядок загрузки (миры) |
| ChatPlaytime | loadbefore | Плагин должен загрузиться раньше ChatPlaytime |

Событие `PlayerPreLoginEvent` — устаревшее в новых версиях Bukkit; работоспособность
на 1.21.x требует проверки/замены на `AsyncPlayerPreLoginEvent`.

### 2.3. Библиотеки (pom.xml)
- `local.plugins:placeholderapi:2.12.3` — provided.
- `org.jetbrains:annotations:24.1.0` — provided.

### 2.4. База данных
- MySQL (опционально, только при `deny-join.enable: true`): общая для серверов сети
  таблица замороженных игроков. Драйвер JDBC берётся из сервера (зависимость в pom не объявлена).
- Внешняя команда: консольная команда `updatepvp <ник> 0` (плагин PvP-статуса, вне этого модуля).

## 3. Архитектура (структура пакетов)

Все классы в одном пакете `org.dimasik.holyfreeze`:

```
org.dimasik.holyfreeze
├── HolyFreeze       — главный класс: конфиг, БД, команды, листенер, PAPI, задача статусов (1 с)
├── Freeze           — сеанс заморозки одного игрока: задачи сообщений/title, телепорт, возврат
├── StatusFreeze     — enum статусов персонала: NONE, CHECKING, AFK
├── CommandFreeze    — CommandExecutor+TabExecutor команд /freezing, /afkstaff, /prova
├── ListenerFreeze   — все блокирующие события + вход/выход игрока
├── PAPIFreeze       — экспансия PlaceholderAPI (идентификатор holyfreeze)
└── DatabaseManager  — прямой JDBC-доступ к MySQL (таблица player_servers)
```

Статические поля главного класса: `freezeHashMap` (UUID → Freeze, активные заморозки),
`config`, `database`, `serverName`, `enableBlockJoin`, `kickMsg`.

## 4. Функциональные требования

### 4.1. Команды (все — только для игроков)

| Команда | Алиас | Право | Описание |
|---|---|---|---|
| `/freezing [игрок] [-s]` | `/freeze` | `holyfreeze.use` | Заморозить/разморозить игрока. Повторный вызов тем же проверяющим (или при его офлайне) снимает заморозку. Флаг `-s` (второй аргумент) — заморозить без телепорта на площадку проверки |
| `/afkstaff` | — | `holyfreeze.use` | Переключить собственный статус AFK (Title «AFK» каждую секунду, движение блокируется) |
| `/prova` | — | `holyfreeze.use` | Переключить собственный статус CHECKING «на проверке» (Title «На проверке») |

Сообщения команд захардкожены в коде (не в конфиге):
- `&b&l▶ &fИспользование: &6/<команда> [игрок]` (вызов без аргументов);
- «Вы не можете заморозить себя.»; «Игрок разморожен.»; «Игрок заморожен.»;
  «Игрок не заморожен.» (цель офлайн); «Вы не замораживали данного игрока!»
  (заморозил другой проверяющий, находящийся онлайн);
- `[Staff] Афк включен!` / `[Staff] Афк выключен!` / `[Staff] Вы начали проверку!` /
  `[Staff] Вы закончили проверку!`;
- «Команду может использовать только игрок.» — при вызове с консоли.

TabComplete для `/freezing`/`/freeze`: ники онлайн-игроков по префиксу.

### 4.2. Механика заморозки (`Freeze.start()`)
1. При `deny-join.enable` — запись ника игрока в таблицу `player_servers` (см. §6).
2. Консольная команда `updatepvp <ник> 0` (снятие PvP-флага внешним плагином).
3. Запоминается исходная локация `suspectLocation`.
4. Если флаг `-s` не задан — телепорт на локацию проверки из `config.yml` (`location.*`,
   мир по умолчанию `spawn`).
5. Запускаются периодические задачи:
   - **сообщения** (каждые 600 тиков = 30 с, сразу при старте): блок строк в чат —
     «Вы подозреваетесь в использовании читов, поэтому были заморожены!», инструкция
     отправить логин AnyDesk в чат в течение 7 мин., предупреждение о блокировке при
     отказе/выходе/игноре. Цвета в HEX-формате `&x&E&D&2&4&2&9` и `&`-коды;
   - **title** (каждые 60 тиков = 3 с): заголовок «ПРОВЕРКА НА ЧИТЫ» и подзаголовок
     с инструкцией следить за чатом.

### 4.3. Разморозка (`Freeze.stop()`)
1. При `deny-join.enable` — удаление записи из `player_servers`.
2. Отмена задач сообщений и title.
3. Если была заморозка с телепортом — задача возврата (каждый тик, счётчик от 10 вниз):
   - если игрок в радиусе 2.5 блока по каждой из координат X/Y/Z от точки проверки —
     показывается title «Вы разморожены!» с отсчётом «Телепортация обратно через: N»;
     по достижении 0 — телепорт на исходную локацию, сообщение `&a▶ &fТелепортация...`;
   - если игрок покинул область проверки — телепортация отменяется, сообщение
     «Вы покинули область, телепортация отменена!».

### 4.4. Выход/кик проверяемого (`stopKick`)
- При Quit — проверяющему (если онлайн) сообщение «Проверяемый покинул игру. Его нужно заблокировать.»;
  задачи отменяются, **запись в player_servers остаётся** (вход на другие серверы заблокирован).
- При Kick — то же без сообщения.
- При повторном Join замороженного (тот же UUID в `freezeHashMap`) — `updatePlayer()`:
  задачи перезапускаются на новом объекте Player.

### 4.5. Блокируемые события (ListenerFreeze, для замороженного)
| Событие | Поведение |
|---|---|
| `PlayerMoveEvent` | отмена при смене X/Y/Z (поворот головы разрешён); отдельно то же для статуса AFK |
| `EntityDamageEvent` | отмена любого урона замороженному |
| `EntityDamageByEntityEvent` | отмена, если замороженный — атакующий |
| `PlayerInteractEvent` | отмена всех взаимодействий |
| `InventoryClickEvent` | отмена кликов в инвентаре |
| `PlayerTeleportEvent` | отмена телепортов |
| `PlayerDropItemEvent` | отмена выбрасывания предметов |
| `PlayerAttemptPickupItemEvent` | отмена поднятия предметов |
| `PlayerCommandPreprocessEvent` | отмена всех команд, **кроме** `/m`, `/msg`, `/r`, `/reply`, `/message` (переписка с проверяющим разрешена) |
| `PlayerJumpEvent` (Paper) | отмена прыжков |

### 4.6. Блокировка входа на другие серверы (`deny-join`)
- `PlayerPreLoginEvent`: по нику из общей таблицы `player_servers` определяется сервер,
  где игрок заморожен; если он отличается от текущего (`deny-join.server`) —
  `disallow(KICK_OTHER)` с сообщением `deny-join.kick-message` (плейсхолдер `%server%`
  заменяется на имя сервера заморозки).
- При выключении плагина (`onDisable`) — `removePlayersByServer()`: очистка всех
  записей текущего сервера (предполагается перезапуск, заморозки не переживают рестарт).

### 4.7. Статусы персонала
- Карта `statusFreezeHashMap` (UUID → StatusFreeze), задаётся командами `/afkstaff`, `/prova`.
- Задача раз в 20 тиков: игрокам со статусом AFK — title «AFK», со статусом CHECKING —
  title «На проверке» (duration 30 тиков).
- Статус AFK также запрещает движение (см. §4.5).

### 4.8. Плейсхолдеры (PlaceholderAPI, идентификатор `holyfreeze`)
| Плейсхолдер | Значение |
|---|---|
| `%holyfreeze_status%` | `""` (нет статуса/NONE), `&#E531FB На проверке` (CHECKING, HEX-цвет), `&#E531FB AFK` (AFK) |

Автор экспансии — `Dimasik`, версия экспансии — 1.0.0, `persist() = true`.

## 6. Хранение данных

### 6.1. Память
- `HolyFreeze.freezeHashMap: HashMap<UUID, Freeze>` — активные заморозки.
- `HolyFreeze.statusFreezeHashMap: HashMap<UUID, StatusFreeze>` — статусы персонала.

### 6.2. MySQL (только при `deny-join.enable: true`)
Таблица (создаётся автоматически асинхронно):
```sql
CREATE TABLE IF NOT EXISTS player_servers (
    nickname    VARCHAR(16) PRIMARY KEY,
    server_name VARCHAR(64) NOT NULL
)
```
Операции `DatabaseManager` (все асинхронные, `CompletableFuture`, авто-реконнект
`autoReconnect=true`):
- `addPlayer(nickname)` — `INSERT ... ON DUPLICATE KEY UPDATE server_name = ?`;
- `getServerByPlayer(nickname)` — `SELECT server_name ...`;
- `removePlayer(nickname)` — `DELETE WHERE nickname = ?`;
- `removePlayersByServer()` — `DELETE WHERE server_name = ?` (при выключении плагина).

Заморозки не сохраняются между перезапусками (после рестарта `freezeHashMap` пуст).

## 7. Интеграции
- **PlaceholderAPI** (жёсткая зависимость): экспансия `holyfreeze` (см. §4.8).
- **Внешняя команда** `updatepvp <ник> 0` — выполняется консолью при заморозке
  (снятие PvP-режима, плагин вне этого модуля).
- **Multiverse-Core** — softdepend (порядок загрузки), **ChatPlaytime** — loadbefore.
- Vault / PlayerPoints и прочие экономики не используются.

## 8. Сценарий работы
1. Проверяющий вызывает `/freeze <ник>` (или `/freeze <ник> -s` без телепорта).
2. Игрок телепортируется на площадку проверки, ему начинают приходить инструкции
   (чат каждые 30 с + title каждые 3 с), все действия блокируются, кроме личных сообщений.
3. При `deny-join` ник попадает в общую таблицу — вход на другие серверы сети закрыт.
4. Если игрок выходит — проверяющему приходит уведомление «заблокировать», вход на
   другие серверы остаётся закрытым до `/freeze` (разморозки) или рестарта.
5. Проверяющий повторно вызывает `/freeze <ник>` — задачи останавливаются, игрок
   (если стоит в зоне проверки) через 10 с возвращается на исходную локацию.
6. Параллельно персонал помечает себя `/afkstaff` или `/prova` — статус виден в
   табличке/чате через `%holyfreeze_status%`.

## 9. Особенности реализации и известные ограничения
- Все игровые тексты (инструкции AnyDesk, title, сообщения команд) захардкожены
  в Java-коде; в конфиге только локация и параметры deny-join.
- `PlayerPreLoginEvent` — синхронное обращение к БД через `.get()` внутри обработчика;
  событие устарело и в новых версиях заменяется на `AsyncPlayerPreLoginEvent`.
- Хранение заморозок только в памяти: рестарт сервера сбрасывает проверки и
  записи в `player_servers` текущего сервера (`removePlayersByServer` в `onDisable`).
- «Заморозку» может снять любой игрок с правом `holyfreeze.use`, если оригинальный
  проверяющий офлайн (проверяется только ник проверяющего).
- Право единое на все три команды — `holyfreeze.use`; отдельных админ-прав нет.
- `Freeze.updatePlayer()` восстанавливает задачи после релеога замороженного,
  но телепорт на площадку при релогине не повторяется.
- Учёт по UUID, запись в БД — по нику (VARCHAR(16)).

## 10. Сборка
```
mvn -pl HolyFreeze package     # из каталога modules (или mvn package в HolyFreeze)
```
Особенностей shade/релокации нет; placeholderapi и annotations — provided
(JDBC-драйвер MySQL должен присутствовать на сервере).
