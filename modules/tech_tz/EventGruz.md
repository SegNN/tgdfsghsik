# Техническое задание — модуль EventGruz

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/EventGruz`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | EventGruz |
| Артефакт (Maven) | `EventGruz` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT |
| Главный класс | `org.dimasik.eventgruz.EventGruz` |
| API-версия Bukkit | 1.16 |
| Авторы (plugin.yml) | не указаны |

**Назначение:** под-ивент «Груз» для системы EventManager — появление в случайной точке
мира `world` уникальной структуры (WorldEdit-схематика) с четырьмя сундуками-тайниками.
Груз бывает трёх типов: **мирный** (без PvP, при открытии игроков рядом отталкивает),
**взрывной** (PvP; при открытии — взрыв и урон по дальности) и **смертельный**
(PvP; шахта-куб: замедление внутри, сундуки на 11 блоков ниже точки). Через 5 минут
после спавна груз «открывается»: создаются четыре 54-слотовых инвентаря, которые
 gradually (раз в 2 тика) заполняются случайным лутом LootManager (уровень 1/2/3 по типу);
игроки забирают предметы напрямую из сундуков (анти-спам по кулдауну 4 тика).
Ещё через 5 минут груз удаляется: откат схемы, удаление региона/голограмм, статус
удаляется из `/event`.

## 3. Архитектура (структура пакетов)

```
org.dimasik.eventgruz
├── EventGruz     — главный класс: GruzManager (листенер), команда /gruz
│                   (внутренний класс GruzCommand); onDisable → removeGruz()
└── GruzManager   — вся логика ивента (Listener): спавн (точка, схема, broadcast по типу),
                    регион, 4 инвентаря/голограммы/частицы по типу, таймер фаз (5+5 мин),
                    открытие (взрыв/отталкивание), наполнение сундуков лутом,
                    клики по сундукам, анти-спам изъятия, куб замедления (createStan),
                    запрет жемчуга/хоруса в кубе, удаление и очистка; enums:
                    GruzState {GRUZ_WAITING, GRUZ_OPENED, GRUZ_NOT_SPAWNED} и
                    GruzType {PEACEFUL, EXPLOSIVE, DEATH}
```

## 4. Функциональные требования

### 4.1. Команда `/gruz` (внутренний класс `GruzCommand`; алиасов нет)
Право на команду: `events.admin` (plugin.yml, на всю команду).
| Синтаксис | Поведение |
|---|---|
| `/gruz` | «Использование: /gruz [spawn/remove/settimer]» |
| `/gruz spawn <peaceful\|explosive\|death>` | Запустить ивент; тип = `GruzType.valueOf(верхний регистр)`, некорректный → usage. Если груз уже есть — warning в лог («Груз уже существует…»), отправителю тишина |
| `/gruz settimer <секунды>` | Перезапустить таймер текущей фазы с новым временем |
| `/gruz remove` | Немедленно удалить груз |

### 4.2. Права (permissions)
| Право | Где объявлено | Назначение |
|---|---|---|
| `events.admin` | plugin.yml (команда `gruz`) | Доступ ко всей команде |

Больше прав нет; взаимодействие игроков с сундуками правами не ограничено.

### 4.3. Типы груза
| Тип | Схематика | displayName (HEX) | PvP в регионе | Уровень лута | Открытие | Расположение сундуков (offset от точки) |
|---|---|---|---|---|---|---|
| `peaceful` | `gruz_peaceful.schem` | «Мирный груз» (зелёный HEX) | DENY | 1 | отталкивание игроков в радиусе 10 от точки-4Y | (0,−1,4), (−4,−1,0), (0,−1,−4), (4,−1,0) |
| `explosive` | `gruz_explosive.schem` | «Взрывной груз» (оранжево-красный) | ALLOW | 2 | взыв power 2.0 (без огня/разрушений) + урон игрокам в радиусе 25 | как peaceful |
| `death` | `gruz_deadly.schem` | «Смертельный груз ☠» (красный) | ALLOW | 3 | отталкивание игроков в радиусе 10 от точки−11Y (эпицентр −15Y) + куб замедления | (−3,−11,3), (4,−11,3), (4,−11,−4), (−3,−11,−4) |

Точка спавна: x,z ∈ [-2500, 2500], y = highestBlockYAt + 1, смещение +0.5/+0.5/+0.5.

### 4.4. Старт (`start`)
1. Требуется отсутствие текущего груза (`currentGruzLocation == null`); мир жёстко `world`.
2. Broadcast-блок выбранного типа: ASCII-рамка, имя, «Появился на координатах», X/Y/Z (уникальные HEX-палитры для каждого типа).
3. Вставка схематики WorldEdit (`ignoreAirBlocks(true)`), EditSession для отката.
4. Дополнительно:
   - задача частиц (каждые 4 тика): для каждого из 4 мест сундуков кольцо `LARGE_SMOKE` (радиус 0.65) на уровне сундука и кольцо `FLAME` (радиус 0.5) на +1.0 (для death — уровни −11.5, для остальных −1.5);
   - регион WorldGuard `gruz_event`;
   - 4 голограммы DecentHolograms (`gruz_hologram_X_Y_Z`) над каждым сундуком (death: −9.5 по Y, остальные: +0.5);
   - для death — `createStan(loc, 50, 600)`: куб со стороной 50 на 600 с: раз в секунду игрокам внутри — `SLOWNESS` (30 тиков, усил. 0), рисование куба частицами `DUST` (шаг 0.75, цвет fromBGR(16759867)); центр в `activeCubes`;
   - 4 пустых инвентаря 54 слота с именем = displayName (создаются заранее, наполняются при открытии);
   - запись статуса в EventManager (ключ `gruz`);
   - таймер фазы WAITING: **300 с** (захардкожено).

### 4.5. Регион WorldGuard `gruz_event`
- Кубоид ±40 X/Z, Y 0..255 (сдвиг +1 при отрицательных координатах точки).
- Флаги: `USE = DENY`, `PVP =` DENY для peaceful / **ALLOW** для explosive и death, `holyliteitems = DENY` (кастомный флаг, ищется по имени), `CHEST_ACCESS = DENY`, `TNT = DENY`, `OTHER_EXPLOSION = DENY`, `FIRE_SPREAD = DENY`, `LAVA_FIRE = DENY`.

### 4.6. Фазы и таймер
- `GRUZ_WAITING` (300 с): каждую секунду — звук `UI_BUTTON_CLICK` (pitch 0.5) в точке груза, обновление голограмм («Будет открыт через M мин., S сек.») и строки `/event` («…и взорвется через M мин., S сек.» — формулировка едина для всех типов). По нулю — `openGruz()`.
- `GRUZ_OPENED` (300 с): та же секунда-логика, тексты «Будет закрыт через…» / «…и будет удален через…». По нулю — `removeGruz()`.
- `setGruzTimer(сек)` отменяет текущую задачу и запускает новую с новым временем (действует на текущую фазу).

### 4.7. Открытие (`openGruz`)
- state = GRUZ_OPENED.
- Взрывной: `World.createExplosion(loc+2Y, 2.0F, false, false)` (без огня и разрушения блоков) + всем игрокам в радиусе 25 — `damage(24.0 * дистанция)` (урон растёт с расстоянием — особенность кода, см. §9).
- Мирный: игрокам в радиусе 10 от точки — отброс (вектор от точки−4Y, множитель 1.5).
- Смертельный: игрокам в радиусе 10 от точки−11Y — отброс от точки−15Y.
- Затем для каждого из 4 мест — `createInventory(location)`:
  - создаётся новый инвентарь 54 слота (title = displayName);
  - объём лута: `27 + rnd(0..26)` предметов (итого 27..53);
  - `new LootAPI().getRandomItems(count, level)` (level 1/2/3);
  - предметы появляются по одному каждые 2 тика в случайном пустом слоте (задача живёт, пока есть предметы и место).

### 4.8. Взаимодействие игроков
- `PlayerInteractEvent` (RIGHT_CLICK_BLOCK) по блоку в одном из 4 мест сундуков: событие отменяется; при GRUZ_OPENED — открыть соответствующий инвентарь. До открытия — ничего.
- `InventoryClickEvent` в инвентаре с заголовком displayName: если взят предмет (не AIR) — анти-спам через `Material.BEDROCK` cooldown 4 тика: первый клик ставит кулдаун, повторный в течение кулдауна — отмена клика + action bar «Вы забираете предметы слишком быстро!» (Adventure Component). Иначе клики не ограничены — предметы забираютсяShift/обычным кликом.
- Внутри куба 50×50×50 (центр в `activeCubes`, проверка ±25) запрещены: ПКМ жемчугом конца (`PlayerInteractEvent`, отмена), поедание плода хоруса (`PlayerItemConsumeEvent`, отмена).

### 4.9. Удаление (`removeGruz`)
- Удаление ключа `gruz` из реестра EventManager; state = GRUZ_NOT_SPAWNED.
- Откат схематики (`editSession.undo`), удаление региона `gruz_event`.
- Закрытие инвентарей у всех зрителей, очистка карт инвентарей/голограмм (голограммы удаляются через DHAPI).
- Отмена таймера, сброс `currentGruzLocation`/`currentGruzType`.
- `onDisable` вызывает `removeGruz()`.
- Итогового broadcast/топа (в отличие от EventContainer) нет.

### 4.10. Обрабатываемые события
- `PlayerInteractEvent` (два обработчика: клики по сундукам; жемчуг),
- `PlayerItemConsumeEvent` (плод хоруса),
- `InventoryClickEvent` (анти-спам изъятия),
- команда `/gruz`.

Плейсхолдеров в конфигах/сообщениях нет (только подстановки координат/времени в коде).

## 8. Сценарий работы (основной поток)
1. Подготовка: EventManager (голосование, конфиг `items.gruz.commands`) выполняет `gruz spawn peaceful|explosive|death` (или админ вручную).
2. Старт: случайная точка, вставка схемы, broadcast с координатами, регион, голограммы/частицы, (death — куб замедления), статус `/event`; таймер 5 мин.
3. Ожидание: игроки собираются; в мирном грузе PvP запрещён, во взрывном/смертельном — разрешён; сундуки не открываются.
4. Открытие: взрыв/отброс по типу; 4 инвентаря начинают наполняться лутом (по предмету каждые 2 тика).
5. Процесс: ПКМ по сундуку → инвентарь; игроки забирают предметы (кулдаун 4 тика на клик с предметом); жемчуг/хорус в зоне (death) запрещены; таймер 5 мин.
6. Завершение: таймер 0 или `/gruz remove` / `onDisable` — откат схемы, удаление региона/голограмм, закрытие инвентарей, удаление статуса `/event`. Топа игроков нет.

## 9. Особенности реализации и известные ограничения
- Урон взрывного груза **растёт** с расстоянием (`24.0 * distance`) — дальние игроки получают больше урона, чем стоящие рядом; похоже на инверсию задуманного.
- Формулировка статуса `/event` всегда «взорвется через…», даже для мирного груза.
- Отсутствует проверка типа поверхности/жидкостей при выборе точки (груз может встать над водой; y = highest+1).
- Оба обработчика `PlayerInteractEvent` независимы; анти-телепорт действует только там, где живёт куб (тип death), у peace/explosive `activeCubes` пуст.
- Кулдаун изъятия реализован через `player.setCooldown(Material.BEDROCK, 4)` — клиент может видеть иконку кулдауна бедрока в инвентаре (хитрость, а не API-курдаун).
- `setGruzTimer` перезапускает таймер, но время фазы WAITING при открытии сбрасывается на 300 с захардкоженно (поле `timeLeft = 300` в новом таймере после `openGruz` — точнее, `setGruzTimer` задаёт произвольное время для любой фазы).
- Классы содержат дублированные большие HEX-broadcast'ы для трёх типов — при изменении текста править в трёх местах.
- Инвентари с лутом не защищены от одновременного опустошения несколькими игроками — ограничение только кулдаун клика.
- `gruzTime` публикуется для чтения, но нигде вне менеджера не используется.

## 10. Сборка
```
mvn -pl modules/EventGruz -am package   # из корня репозитория
```
- Зависимости `local.plugins:*` (worldedit, worldguard, decentholograms) должны быть установлены в локальном Maven-репозитории.
- `EventManager` и `LootManager` — модули того же reactor (собираются с `-am`).
- Shade отсутствует; jar без зависимостей.
