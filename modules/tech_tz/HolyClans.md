# Техническое задание — модуль HolyClans

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/HolyClans`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | HolyClans |
| Артефакт (Maven) | `HolyClans` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0 |
| Главный класс | `org.impldev.holyclans.HolyClans` |
| API-версия Bukkit | 1.21 (сборка против paper-api 1.21.4-R0.1-SNAPSHOT) |
| Автор (plugin.yml) | HolyZako |
| Описание | Клановая система |

**Назначение:** система кланов для Minecraft-сервера: создание кланов за валюту
(Vault), казна и налоги, клановые очки и уровни, приглашения/исключения, роли
(лидер/заместитель/участник), защита от урона по соклановцам (toggle PvP),
клановый чат, до 3 клановых точек дома с телепортом, выбор «цвета брони
подсветки соклановцев», топ кланов и GUI-меню на все разделы.

**Важно:** войн, территорий (приватов), альянсов и призов в коде нет — набор
механик ограничен перечисленным выше.

---

## 2. Требования к окружению и зависимости

### 2.1. Сервер
- Paper/Spigot с поддержкой API 1.21 (ветка mc-1.21.4; используются
  Adventure-компоненты, `ItemMeta.displayName(Component)`, паттерн `instanceof`).
- Java 21 (`maven.compiler.release=21` в родительском POM).

### 2.2. Плагины
| Плагин | Зависимость в plugin.yml | Версия из pom.xml | Область применения | Обязательность |
|---|---|---|---|---|
| Vault | `depend` | 1.7.3 | Экономика: создание клана, казна, покупка очков/слотов | Жёсткая (по plugin.yml); при отсутствии Economy хук падает в warning, экономические операции недоступны |
| WorldGuard | `softdepend` | 7.0.13 | Запрет `/clan sethome` в чужих регионах | Мягкая (используется, только если плагин обнаружен) |
| WorldEdit | `softdepend` | 7.3.16 | BukkitAdapter для координат WorldGuard | Мягкая (нужен вместе с WorldGuard) |
| PlaceholderAPI | `softdepend` | 2.12.3 | Экспансия плейсхолдеров `%holyclans_*%` | Мягкая (регистрируется только при наличии) |

### 2.3. Библиотеки
- jetbrains annotations 24.1.0 (provided) — только аннотации.
- Всё остальное (Vault/WorldGuard/WorldEdit/PlaceholderAPI) — provided,
  берётся с сервера. Shade дополнительных библиотек не выполняет
  (в jar попадает только код плагина).

### 2.4. Хранилище
- Только YAML: один файл на клан в `plugins/HolyClans/clans/<имя>.yml`.
- MySQL/SQL-режима нет.

```
org.impldev.holyclans

│                          регистрация команды /clan и листенеров, таймеры
│                          (очистка инвайтов 60 c, автосохранение 5 мин), PAPI-экспансия
├── Clan                 — модель клана (имя, лидер, казна, очки, уровень, слоты, pvp,
│                          glowColor/glowMode, участники, точки дома); проверки ролей
├── ClanMember           — запись участника (uuid, имя, роль)
├── ClanRole             — enum LEADER / DEPUTY / MEMBER
├── ClanData             — хранилище: yml-файл на клан; кеши byName/byPlayer
│                          (ConcurrentHashMap); create/save/saveAll/delete; топ по очкам
├── ClanCommand          — команда /clan (CommandExecutor + TabCompleter), вся логика
│                          подкоманд, подтверждения, приглашения, хомы
├── ClanListener         — события: урон по соклановцам, чат (создание клана по вводу
│                          имени + клан-чат), создание клана с проверками и оплатой
├── ClanPlaceholders     — экспансия PlaceholderAPI (идентификатор `holyclans`)
├── InviteManager        — активные приглашения (record Invite: клан, пригласивший,
│                          момент истечения), ленивая очистка + cleanup по таймеру
├── ConfirmManager       — отложенные подтверждения DELETE/NEWLEADER (30 с),
│                          record Pending(action, target, expiresAt)
├── RegionCheck          — проверка WorldGuard: находится ли локация в чужом регионе
│                          (игрок не owner и не member; __global__ игнорируется)
├── Texts                — цвета, парсер legacy-строк с HEX (формат &x&F&F&F&F&F&F),
│                          снятие italic, форматирование чисел с пробелами
└── menu                 — GUI-меню

   │                      определяет «свои» инвентари
   ├── Menus             — фабрика предметов меню (item/glass/back/close,
   │                      окрашенный LEATHER_CHESTPLATE с меткой выбранного цвета)
   ├── MenuService       — Listener: открытие всех меню (отложено на 1 тик против
   │                      ghost items), отмена любых кликов/перетаскиваний,
   │                      диспетчеризация кликов по слотам для каждого меню
   ├── CreateMenu        — «Создание клана», 45 слотов
   ├── MainMenu          — главное меню клана, 54 слота
   ├── UpgradeMenu       — «Улучшение клана» (уровень, очки), 45 слотов
   ├── GlowMenu          — «Цвет брони» (до 24 цветов + режим подсветки), 54 слота
   ├── MembersMenu       — «Список участников» (головы + покупка слотов), 54 слота
   ├── HomesMenu         — «Клановые точки» (3 кровати), 45 слотов
   ├── TreasuryMenu      — «Казна клана» (внесение/снятие фиксированных сумм), 54 слота
   └── ClanListMenu      — «Список кланов» (топ по очкам, до 28 кланов), 54 слота
```

## 4. Функциональные требования

### 4.1. Команда `/clan`
Зарегистрирована в plugin.yml (алиасов нет; usage-строка перечисляет подкоманды).
Только для игроков (консоль получает «Команда только для игроков.»).
Каждая подкоманда требует членство в клане (`requireClan`), если не указано иное.

| Команда | Роль в клане | Описание |
|---|---|---|
| `/clan` (без аргументов или неизвестная) | любая | Открыть меню: без клана — CreateMenu, с кланом — MainMenu |
| `/clan help` | — | Справка по командам (текст зашит в коде) |
| `/clan top` | — | Топ-10 кланов по очкам (`#N \| имя очков`) |
| `/clan money` | участник | Баланс казны (число с разделителями-пробелами) |
| `/clan invest <сумма>` | участник | Пополнить казну: списание с баланса игрока (Vault), `treasury += сумма` |
| `/clan withdraw <сумма>` / `/clan take <сумма>` | лидер или зам | Снять из казны на свой баланс; суммы ≤ 0 и больше казны отклоняются |
| `/clan members` | участник | Открыть меню участников (MembersMenu) |
| `/clan invite <ник>` | лидер или зам | Пригласить онлайн-игрока (см. §4.3) |
| `/clan accept` | — (без клана) | Принять активное приглашение |
| `/clan decline` | — | Отклонить активное приглашение |
| `/clan kick <ник>` | лидер или зам | Исключить участника (лидера исключить нельзя) |
| `/clan delete` | лидер | Запрос подтверждения на удаление клана |
| `/clan newleader <ник>` | лидер | Запрос подтверждения на передачу лидерства участнику |
| `/clan confirm` | лидер | Подтвердить отложенное действие (delete/newleader) |
| `/clan cancel` | — | Отменить отложенное действие |
| `/clan glow` | лидер или зам | Открыть меню выбора цвета брони (GlowMenu) |
| `/clan pvp` | лидер или зам | Переключить урон по соклановцам вкл/выкл |
| `/clan sethome` | лидер | Установить клановую точку дома (см. §4.6) |
| `/clan home` | участник | Телепорт на первую доступную точку дома |
| `/clan list` | — | Открыть список всех кланов (ClanListMenu) |
| `/clan chat` | участник | Переключить режим клан-чата для себя |
| `/clan leave` | участник (не лидер) | Покинуть клан (лидеру запрещено) |

**Tab-дополнение:**
- 1-й аргумент: 18 видимых подкоманд `help, top, money, invest, withdraw, take,
  members, invite, kick, delete, newleader, glow, pvp, sethome, home, list, chat,
  leave` (скрытые служебные `accept/decline/confirm/cancel` в списке нет, но работают).
- 2-й аргумент: `invite` — дефолтный список онлайн-игроков (`null`);
  `kick`, `newleader` — ники участников своего клана.

### 4.2. Права (permissions)
Плагин **не объявляет и не проверяет ни одного права**. В `plugin.yml` секция
`permissions` отсутствует, вызовов `hasPermission` в коде нет. Весь доступ
регулируется исключительно членством и ролью в клане (лидер / заместитель /
участник) либо фактом нахождения в клане.

### 4.3. Создание клана
Выполняется через GUI (не командой):
1. `/clan` без клана → CreateMenu; кнопка «Создать клан» (слот 21) закрывает меню,
   переводит игрока в режим ожидания ввода имени (`awaitingName`) и просит ввести
   название в чат.
2. Следующее сообщение игрока в чате перехватывается (AsyncPlayerChatEvent,
   приоритет LOWEST, отмена события) и обрабатывается в основном потоке
   (`ClanListener.handleCreateName`).
3. Валидация: длина ≤ `max-name-length` (12) и соответствие регулярному выражению
   `^[a-zA-Zа-яА-ЯёЁ0-9&]+$` (латиница, кириллица, цифры и `&` для кодов цвета);
   уникальность имени (без учёта регистра); игрок не состоит в клане;
   баланс ≥ `creation-cost` (5 000 000).
4. Оплата списывается через Vault; при неудачном `create()` деньги возвращаются.
5. Новый клан: уровень 1, казна 0, очки 0, слоты `initial-slots` (2), pvp=false,
   glowColor=-1, glowMode=OFF, единственный участник — лидер.

### 4.4. Приглашения (InviteManager)
- `/clan invite <ник>`: цель обязана быть онлайн (`getPlayerExact`), не состоять
  ни в одном клане, не иметь уже активного приглашения от этого же клана;
  в клане должен быть свободный слот (`members < slots`).
- Приглашение живёт `invite-timeout-seconds` (300 c); просроченные вычищаются
  лениво при обращении и задачей `cleanup()` каждые 1200 тиков (60 c).
- Приглашённому отправляется кликабельное сообщение Adventure:
  `[Принять приглашение]` → `/clan accept`, `[Отменить приглашение]` → `/clan decline`
  (hover-подсказки); подпись «Отклонится через 5 минут» зашита в коде и не зависит
  от конфига.
- Одновременно у игрока может быть только одно приглашение (Map по UUID):
  новое приглашение от другого клана перезапишет старое.
- `accept`: повторная проверка свободных слотов; игрок добавляется с ролью MEMBER;
  всем участникам клана рассылается сообщение о вступлении.

### 4.5. Подтверждения (ConfirmManager)
- Действия `delete` и `newleader` требуют подтверждения: создаётся запись
  `Pending(action, target, expiresAt)` с таймаутом 30 000 мс (зашито в коде).
- Игроку `confirm-spam-count` (10) раз с интервалом 2 тика отправляется сообщение
  с кнопками `[ПОДТВЕРДИТЬ]` (`/clan confirm`) и `[ОТМЕНА]` (`/clan cancel`).
- `confirm` выполняет действие: DELETE — удаление клана (файл + кеши, сообщение
  всем участникам, очистка режима клан-чата); NEWLEADER — смена лидера
  (старый становится MEMBER, новый LEADER).
- Проверка членства в клане в `confirm` выполняется до чтения Pending —
  подтверждение обрабатывается только в контексте текущего клана.

### 4.6. Клановые точки дома
- Максимум 3 точки (индексы 0..2). Точка i доступна, если наигрыш **лидера**
  (статистика `PLAY_ONE_MINUTE`, 72 000 тиков = 1 час) ≥ `home-points.<i+1>`
  (10 / 28 / 46 часов по умолчанию).
- `/clan sethome` (только лидер): при наличии WorldGuard запрещено в чужом регионе
  (`RegionCheck.isInForeignRegion` — регион, где игрок не owner и не member;
  `__global__` пропускается; любая ошибка WG трактуется как «не чужой»);
  точка ставится в первый свободный слот, при заполненности всех трёх —
  перезаписывается слот 2; локация хранится с миром/x/y/z/yaw/pitch.
- `/clan home`: телепорт на первую точку из Map (порядок не гарантирован —
  фактически с наименьшим индексом при LinkedHashMap-загрузке); без кулдауна.
- HomesMenu: клик по установленной точке (зелёная кровать) закрывает меню
  и телепортирует.

### 4.7. Уровни и очки клана (UpgradeMenu)
- Клановое очко покупается за `point-cost` (15 000) с личного баланса игрока
  (любой участник клана).
- Повышение уровня с N на N+1 требует `level-requirements.<N+1>.points` очков
  и `level-requirements.<N+1>.treasury` монет в казне; оба ресурса списываются.
- Таблица требований задана для уровней 2–10. Если требований для следующего
  уровня нет (уровень 10+), применяется fallback: `points = N-1`,
  `treasury = (N-1) * 100 000` — верхнего предела уровня не существует.
- Клик «Повысить уровень» при нехватке ресурсов выдаёт соответствующее сообщение.

### 4.8. Казна (TreasuryMenu)
- Вклад (любой участник): слоты 27/28/29/30 — +1 000 000 / +100 000 / +10 000 / +1 000.
- Снятие (только лидер или зам): слоты 32/33/34/35 — −1 000 / −10 000 / −100 000 /
  −1 000 000 (подписи в меню — «Скоммуниздить … монет»).
- Суммы зашиты в коде; недостаток личных средств/казны отклоняется.
- После операции меню переоткрывается.

### 4.9. Участники и слоты (MembersMenu)
- В клане `slots` мест (лидер + участники); `initial-slots = 2`.
- Меню показывает голову клана (слот 4: имя, уровень, создатель, очки, список
  участников) и до 15 участников (головы по слотам 19–25, 28–34, 37) без лидера;
  пустые открытые места остаются пустыми, места сверх `slots` — красное стекло
  с предложением купить слот.
- Покупка слота (клик по красному стеклу, лидер/зам): `slot-cost` (1 000 000)
  с личного баланса, `slots += 1`. Отображаемых позиций всего 15 — участники
  сверх 16 мест (лидер + 15) в меню не видны, хотя логика приглашений позволяет
  расширяться дальше.
- Действия по голове участника (доступны только лидеру, не на самом себе):
  ПКМ — исключить; Shift+ПКМ — назначить/разжаловать заместителя;
  Shift+ЛКМ — передать лидерство (без дополнительного подтверждения).

### 4.10. Цвет брони / подсветка соклановцев (GlowMenu)
- Слоты цветов (до 24): окрашенные LEATHER_CHESTPLATE из `glow-colors`
  (22 RGB-значения в конфиге; при пустом конфиге — 23 дефолтных из кода).
- Клик по цвету (лидер/зам через `/clan glow` или MainMenu) сохраняет
  `glowColor`; выбранный нагрудник помечается «✔ Этот цвет брони установлен».
- Слот 46 — режим подсветки: клик циклично переключает OFF → TEMP → ON → OFF
  (строки лора отражают текущее состояние).
- **Ограничение:** сохранённые `glowColor`/`glowMode` никак не применяются
  к игрокам — кода окрашивания брони, glow-эффекта или scoreboard-команд в
  плагине нет; значение хранится и отображается в меню.

### 4.11. PvP внутри клана
- `ClanListener.onDamage` (EntityDamageByEntityEvent, приоритет HIGH,
  ignoreCancelled=true): если жертва и атакующий (включая снаряды с
  игроком-стрелком) — игроки одного клана и у клана `pvp=false`, урон отменяется.
- `/clan pvp` (лидер/зам) переключает флаг; самоповреждение не фильтруется
  (attacker == victim игнорируется).

### 4.12. Клан-чат
- `/clan chat` переключает персональный режим; состояние хранится в памяти
  (`clanChatActive`, Set<UUID>) и сбрасывается при выходе из клана/исключении/
  удалении клана, не переживает рестарт сервера.
- Сообщение игрока в режиме клан-чата перехватывается (AsyncPlayerChatEvent,
  LOWEST), отменяется и рассылается всем онлайн-участникам клана в формате
  «Клан-Чат | <ник>: <текст>».

### 4.13. События Bukkit, используемые плагином
| Событие | Приоритет | Назначение |
|---|---|---|
| `EntityDamageByEntityEvent` | HIGH, ignoreCancelled | Отмена урона по соклановцам при pvp=false |
| `AsyncPlayerChatEvent` | LOWEST | Перехват ввода названия клана; клан-чат (использует deprecated API) |
| `InventoryClickEvent` | NORMAL | Обработка кликов во всех меню, отмена перемещений |
| `InventoryDragEvent` | NORMAL | Отмена перетаскивания в меню |

### 4.14. Сообщения и кликабельные элементы
- Все тексты зашиты в код (конфигурируемых сообщений нет), с HEX-цветами
  в legacy-формате `&x&F&F&F&F&F&F` и `&`-кодами; парсер `Texts.color`
  дополнительно снимает курсив (Adventure ITALIC=false).
- Кликабельные кнопки Adventure: `[Принять]`/`[Отменить]` в приглашении
  (runCommand + hover), `[ПОДТВЕРДИТЬ]`/`[ОТМЕНА]` в подтверждениях.
- Числа казны/цен форматируются пробелами-разделителями тысяч (`Texts.num`).

## 5. Конфигурация (`config.yml`)

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `creation-cost` | long | 5 000 000 | Стоимость создания клана (монеты Vault) |
| `max-name-length` | int | 12 | Максимальная длина названия клана |
| `point-cost` | long | 15 000 | Цена 1 кланового очка |
| `slot-cost` | long | 1 000 000 | Цена открытия 1 слота участника |
| `initial-slots` | int | 2 | Начальное число мест в клане (лидер + участники) |
| `invite-timeout-seconds` | long | 300 | Время жизни приглашения, секунды |
| `confirm-spam-count` | int | 10 | Сколько раз отправлять сообщение-подтверждение (каждые 2 тика) |
| `level-requirements.<2..10>.points` | int | см. ниже | Очки, необходимые для перехода на уровень |
| `level-requirements.<2..10>.treasury` | long | см. ниже | Монеты в казне, необходимые для перехода (списываются) |
| `home-points.<1..3>` | int | 10 / 28 / 46 | Часы наигрыша лидера для разблокировки i-й точки дома |
| `glow-colors` | list[int] | 22 значения | RGB-цвета для меню подсветки брони |

Таблица требований по уровням (points / treasury):
| Уровень | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| Очки | 1 | 3 | 6 | 10 | 15 | 21 | 28 | 36 | 45 |
| Казна | 100 000 | 300 000 | 600 000 | 1 000 000 | 1 500 000 | 2 100 000 | 2 800 000 | 3 600 000 | 4 500 000 |

Настройки в коде читаются в момент операции; `/clan reload` отсутствует
(перечитывается только при рестарте плагина, `saveDefaultConfig` при включении).

## 6. Хранение данных

### 6.1. Файлы кланов — `plugins/HolyClans/clans/<имя_в_нижнем_регистре>.yml`
Один файл на клан; загружаются все при старте, сохраняются после каждого
изменения, автосохранение всех раз в 5 минут (6 000 тиков) и при `onDisable`.

```
name: <оригинальное название клана>
leader: <uuid лидера>
treasury: <long, монеты в казне>
points: <int, клановые очки>
level: <int, уровень (по умолчанию 1)>
slots: <int, число мест (по умолчанию 2)>
pvp: <boolean, урон по соклановцам (по умолчанию false)>
glow-color: <int RGB, -1 = не выбран (по умолчанию -1)>
glow-mode: <OFF|TEMP|ON (по умолчанию OFF)>
members:
  <uuid участника>:
    name: <ник>
    role: <LEADER|DEPUTY|MEMBER (по умолчанию MEMBER)>
homes:
  <индекс 0..2>:
    world: <имя мира>
    x/y/z: <double>
    yaw/pitch: <double>
```
При загрузке точки дома, чей мир не загружен на момент старта, молча
пропускаются.

### 6.2. Эфемерные данные (только в памяти, не сохраняются)
- Активные приглашения: `Map<UUID, Invite{clan, inviter, expiresAt}>`.
- Ожидающие подтверждения: `Map<UUID, Pending{action, target, expiresAt}>`
  (таймаут 30 с).
- Режим клан-чата и режим ввода названия клана: `Set<UUID>`.

## 7. Интеграции

### 7.1. Vault (обязательная зависимость)
- Хук `Economy` через ServicesManager при старте; при недоступности — warning
  «Vault не найден: экономика работать не будет.» и все денежные операции
  (создание, invest/withdraw, покупка очков/слотов) становятся недоступны
  (проверки баланса возвращают «недостаточно средств» при `economy() == null`).
- Операции: `withdrawPlayer`/`depositPlayer`/`getBalance` (некий провайдер
  экономики, например EssentialsX/CoinEngine — на усмотрение сервера).

### 7.2. WorldGuard + WorldEdit (мягкая)
- Только одна точка использования: `/clan sethome` запрещён в регионах, где
  игрок не owner и не member (кроме `__global__`). Проверка активна, только
  если плагин WorldGuard обнаружен (`hasWorldGuard()`).

### 7.3. PlaceholderAPI (мягкая)
Экспансия `holyclans` (автор ImplDev, версия 1.0, `persist()=true`), параметры:

| Плейсхолдер | Значение |
|---|---|
| `%holyclans_name%` | Название клана игрока; без клана — `&7Нет` |
| `%holyclans_level%` | Уровень клана; без клана — `0` |
| `%holyclans_points%` | Клановые очки; без клана — `0` |
| `%holyclans_treasury%` | Казна (формат с пробелами); без клана — `0` |
| `%holyclans_members%` | Количество участников; без клана — `0` |
| `%holyclans_role%` | Роль игрока: `Лидер` / `Заместитель` / `Участник`; без клана — пусто |

## 8. Сценарии работы

### 8.1. Создание клана и приглашение
1. Игрок без клана вводит `/clan` → CreateMenu → «Создать клан» → вводит
   название в чат.
2. Валидация имени/уникальности/баланса → списание 5 000 000 → клан создан
   (уровень 1, 2 слота).
3. Лидер `/clan invite <ник>` → цель получает кнопки → `/clan accept` →
   вступление, уведомление клану.

### 8.2. Прокачка
1. Любой участник клана покупает очки за монеты с личного баланса
   (UpgradeMenu, слот 23 «Клановые очки»).
2. При достаточных очках и казне любой участник повышает уровень
   (слот 21 «Повышение уровня») — ресурсы списываются; требования
   следующих уровней растут по таблице §5.

### 8.3. Казна
- Участник вносит фиксированные суммы (TreasuryMenu слева / `/clan invest`).
- Лидер/зам снимает (TreasuryMenu справа / `/clan withdraw`).
- Казна тратится на повышение уровня; остаток выводится на баланс.

### 8.4. Быт клана
- `/clan pvp` — разрешить/запретить урон по своим (по умолчанию запрещён).
- `/clan chat` — приватный чат клана.
- `/clan sethome` лидером (до 3 точек, гейт по наигрышу лидера, не в чужом
  регионе WG), `/clan home` / HomesMenu — телепорт.
- GlowMenu — выбор цвета/режима подсветки (сохраняется, визуально не применяется).
- `/clan top` / ClanListMenu — рейтинг по очкам.

### 8.5. Расформирование
- Лидер `/clan delete` → спам-подтверждение → `/clan confirm` → клан удалён,
   файл удалён, все участники уведомлены; либо `/clan cancel`.
- Передача лидерства: `/clan newleader <ник>` + confirm либо Shift+ЛКМ по
  участнику в MembersMenu (мгновенно).

## 9. Особенности реализации и известные ограничения

- **Права не используются**: нет ни одного permission; всё через роли клана.
- **Сообщения не конфигурируются** — все тексты, включая цены в лорах CreateMenu
  («5 000 000 монеток»), подпись таймаута приглашения («через 5 минут») и
  сообщение sethome с зашитым «из 3 точек», лежат в коде и не следуют за
  изменением config.yml.
- Подсветка брони (`glow-color`/`glow-mode`) сохраняется и отображается в меню,
  но **не применяется визуально** — реализации окрашивания/glow нет.
- `ClanCommand.isValidName` (регулярка без `&`) — мёртвый код: реально
  используется собственный паттерн `ClanListener.NAME_PATTERN` с `&`.
- В `GlowMenu` переменная `modeLine` вычисляется, но не используется (лишний код);
  статус режима в лоре слота 46 строится тремя тернарными строками.
- `AsyncPlayerChatEvent` и `Statistic.PLAY_ONE_MINUTE` — deprecated API
  (работает на 1.21.4, но генерирует предупреждения компилятора; сборка с
  `-nowarn`).
- Уровень клана не ограничен сверху: за пределами таблицы (уровень 10+)
  действует fallback-формула.
- Клановых войн, территорий/приватов, альянсов, кулдаунов на телепорты,
  наград/призов нет (в модуле это отсутствует по построению).
- Точка дома: при перезаполнении `/clan sethome` молча перезаписывает слот 2;
  `/clan home` телепортирует на первую точку Map.
- Часы наигрыша читаются офлайн-статистикой лидера (`PLAY_ONE_MINUTE`/72000);
  исключения трактуются как 0 часов.
- Ввод названия клана через чат: перехватывается любое следующее сообщение,
  включая одно сообщение после клика кнопки (если игрок передумал — название
  уйдёт в обычный чат только после одной неудачной/успешной попытки ввода).
- Сохранение — синхронное на главном потоке (YamlConfiguration.save после
  каждой операции + автосейв раз в 5 минут); при большом числе кланов возможны
  паузы записи диска.
- Потокобезопасность: кеши кланов/игроков/инвайтов/подтверждений —
  ConcurrentHashMap / ConcurrentHashMap.newKeySet.
- Открытие любого меню откладывается на 1 тик (`runTask`) — защита от
  ghost items при открытии из клик-хэндлера.
- Все клики и drag в меню отменяются; обработка только верхнего инвентаря.

## 10. Сборка

```
mvn -pl HolyClans package     # из каталога modules (или mvn package в HolyClans)
```
- Родительский POM задаёт `maven.compiler.release=21` и paper-api
  `1.21.4-R0.1-SNAPSHOT`; maven-shade-plugin 3.5.3 используется в стандартной
  конфигурации родителя (вырезаются подписи META-INF), дополнительных
  релокаций для этого модуля нет.
- Зависимости vault/worldguard/worldedit/placeholderapi/annotations — provided
  (локальные артефакты `local.plugins:*` из `_api-stubs`/репозитория проекта).
- Результат: `target/HolyClans-1.0.jar`.
