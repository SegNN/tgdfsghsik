# Техническое задание — модуль ChatBrackets

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/ChatBrackets`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | ChatBrackets |
| Артефакт (Maven) | `ChatBrackets` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT (версия экспансии — «1.0.0») |
| Главный класс | `org.dimasik.chatbrackets.ChatBrackets` |
| API-версия Bukkit | 1.16 |
| Автор (в экспансии) | `YourName` (шаблонный, не менялся) |

**Назначение:** мини-плагин-провайдер плейсхолдеров PlaceholderAPI для оформления
чата. Берёт префикс игрока из LuckPerms и отдаёт его фрагменты, обёрнутые в
красивые кавычки-ёлочки (« »), с корректным переносом цвета — чтобы чат-формат
типа `%chatbrackets_full% сообщение игрока` рисовал префикс в скобках, а текст
сообщения наследовал цвет. Отдельные плейсхолдеры дают открывающую/закрывающую
скобку в цвете префикса, префикс без жирности и «чистый» первый цвет префикса.

Команд, событий и конфигурации нет — только регистрация PAPI-экспансии.

## 2. Требования к окружению и зависимости

| Зависимость | Версия | Scope | Назначение |
|---|---|---|---|
| PlaceholderAPI | 2.12.3 | provided (`local.plugins:placeholderapi`) | регистрация экспансии |
| LuckPerms | 5.5.53 | provided (`local.plugins:luckperms`) | чтение префикса игрока (через `LuckPermsProvider`) |

- Оба плагина обязательны на сервере: без PlaceholderAPI регистрация экспансии
  невозможна, без LuckPerms `LuckPermsProvider.get()` бросит исключение
  (IllegalStateException) при первом запросе плейсхолдера.
- Сервер: Paper/Spigot API 1.16 (сборка Java 21).

## 3. Архитектура

```
org.dimasik.chatbrackets
└── ChatBrackets — JavaPlugin + внутренний класс ChatBracketsExpansion
    (PlaceholderExpansion, идентификатор "chatbrackets"): парсинг префикса
    LuckPerms, очистка хвостовых &r/&f/пробелов, извлечение цветовых кодов,
    генерация «скобочных» строк
```

Методы-помощники экспансии:
| Метод | Назначение |
|---|---|
| `firstTextIndex(s)` | индекс первого «текстового» (не цветового) символа; корректно пропускает `&x`-HEX-последовательности (14 символов) и обычные `&k`-пары |
| `getFirstColor(prefix)` | «голова» цвета префикса: `&x`-HEX (первые 14 симв., если второй символ `x`) + все последующие подряд идущие `&k`-пары |
| `getNoBold(s)` | удаляет все `&l` (жирный) и `&n` (подчёркнутый) |
| `getLastColor(prefix)` | не используется (мёртвый код) |
| `getFullString(...)` | не используется (мёртвый код) |

## 4. Функциональные требования

### 4.1. Плейсхолдеры (PlaceholderAPI, идентификатор `chatbrackets`)
Общий вход: `player != null`, `LuckPerms.getUserManager().getUser(uuid) != null`,
префикс из `user.getCachedData().getMetaData().getPrefix()` не пуст — иначе `""`.
Перед обработкой из префикса циклично срезаются хвостовые пробелы, `&r`, `&f`.

| Плейсхолдер | Возвращаемое значение |
|---|---|
| `%chatbrackets_begin%` | первый цвет префикса (см. `getFirstColor`) + `«` |
| `%chatbrackets_end%` | `» &r&f ` (закрывающая скобка + сброс цвета) |
| `%chatbrackets_full%` | префикс, в котором после ведущих цветовых кодов вставлена `«`, а в конец добавлено `» &r&f ` (т.е. `цвет«текст_префикса» &r&f `) |
| `%chatbrackets_nobold%` | префикс без `&l`/`&n` (без жирного/подчёркивания) |
| `%chatbrackets_color%` | первый цвет префикса; **только** при праве `holyfreeze.use` или `chatbrackets.color`, иначе `""` (исключения глушатся → `""`) |
| любое другое | `null` (плейсхолдер не найден) |

### 4.2. Права (permissions)
| Право | Назначение |
|---|---|
| `chatbrackets.color` | доступ к плейсхолдеру `%chatbrackets_color%` |
| `holyfreeze.use` | альтернативный доступ к `%chatbrackets.color%` (унаследовано из другого плагина проекта — проверяется тем же условием) |

Права нигде не объявлены (plugin.yml пустой), проверяются только через `Player.hasPermission`.

### 4.3. Команды и события
- Команд нет. События не обрабатываются. Конфигурации нет.

## 8. Сценарий работы
1. Сервер стартует → экспансия `chatbrackets` регистрируется в PAPI
   (при неудаче — warning в лог).
2. Чат-плагин (например, LiteChat) в формате чата запрашивает
   `%chatbrackets_full%` для говорящего.
3. Экспансия берёт префикс из кэша LuckPerms (например `&x&3&1&D&E&2&A[VIP] &r`).
4. Хвостовые `&r`/`&f`/пробелы срезаются → `&x...[VIP]`.
5. После ведущих цветовых кодов вставляется `«`, в конец — `» &r&f `.
6. Игрок пишет сообщение — оно наследует белый/сброшенный цвет после скобки.
7. При остановке сервера экспансия разрегистрируется.

## 9. Особенности реализации и известные ограничения
- `getFirstColor` без try/catch: при префиксе длиной ровно 1 символ
  `prefix.charAt(1)` бросит StringIndexOutOfBoundsException (защита есть только
  в ветке `color`).
- Мёртвый код: `getLastColor` (с потенциально некорректным циклом
  `for (ix = lastColorIndex + 14; ix > 0; ix++)`) и `getFullString` не вызываются.
- `getFirstColor` собирает только подряд идущие с начала строки цветовые коды;
  комбинированные форматы вида `&x...&l` сохранят и `&l`.
- `begin`/`full` не экранируют случай, когда после очистки префикс стал пустым
  (вернётся `«` без цвета).
- Право `holyfreeze.use` в проверке цвета — кросс-плагинная легаси-связка
  (плагин HolyFreeze), не настраивается.
- Идентификатор автора `YourName` — шаблонный, не заменён.
