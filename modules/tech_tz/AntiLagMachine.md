# Техническое задание — модуль AntiLagMachine

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/AntiLagMachine`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | AntiLagMachine |
| Артефакт (Maven) | `AntiLagMachine` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0-SNAPSHOT |
| Главный класс | `org.dimasik.antilagmachine.AntiLagMachine` |
| API-версия Bukkit | 1.16 |
| Авторы | в plugin.yml не указаны |

**Назначение:** анти-лаговый плагин, борющийся с редстоун-машинами («лаггинг-машинами»)
на нагруженном сервере. Делает три вещи:
1) ограничивает частоту кликов игрока по редстоун-активируемым блокам (рычаги, кнопки,
   двери, редстоун-факелы, кафедры) — не чаще одного взаимодействия в 500 мс;
2) при падении TPS сервера ниже 12.0 полностью гасит редстоун-сигналы
   (`BlockRedstoneEvent.setNewCurrent(0)`) и считает «подозрительную активность»
   вокруг каждого источника сигнала; игроки, находящиеся рядом с часто срабатывающим
   редстоуном при низком TPS, после двух срабатываний автоматически банятся
   командой `shame ban <ник>` от имени консоли;
3) глобальный рейт-лимитер редстоун-событий — блок (кроме раздатителя и дроппера)
   может менять сигнал не чаще одного раза в 250 мс.

Модуль предельно мал: один Java-класс, без команд, прав, конфигурации и хранилищ.

## 2. Требования к окружению и зависимости

### 2.1. Сервер
- Paper/Spigot с поддержкой API 1.16 (сборка под ветку mc-1.21.4, Java 21 —
  из `maven.compiler.release` родительского POM).
- Используются `Bukkit.getTPS()` — метод Paper/Spigot (в чистом Bukkit API отсутствует).

### 2.2. Плагины
| Плагин | Область применения | Обязательность |
|---|---|---|
| Shame | Получатель команды `shame ban <ник>` (хардкод в коде) | Фактически требуется при срабатывании анти-лаг бана |

### 2.3. Библиотеки
- Нет. Раздел `<dependencies>` в pom пуст; Bukkit/Paper API приходит provided из
  родительского POM (`io.papermc.paper:paper-api:1.21.4-R0.1-SNAPSHOT`).

## 3. Архитектура

```
org.dimasik.antilagmachine
└── AntiLagMachine — единственный класс: JavaPlugin + Listener; вся логика
    (кулдауны кликов, гашение редстоуна при низком TPS, автобан лаггеров)
```

Поля состояния (все в памяти, персистентности нет):
| Поле | Тип | Назначение |
|---|---|---|
| `blocks` | `HashMap<Location, Integer>` (public) | счётчик редстоун-событий по локации при TPS ≤ 12 |
| `players` | `HashMap<Player, Integer>` (public) | счётчик «попаданий» игрока в зону подозрительного редстоуна |
| `lastUseTimes` | `HashMap<UUID, Long>` (private) | время последнего клика игрока по редстоун-блоку |
| `lastRedstoneTimes` | `HashMap<Block, Long>` (private) | время последнего изменения сигнала блока |
| `COOLDOWN` | `static final long = 500` | кулдаун кликов игрока, мс |
| `REDSTONECOOLDOWN` | `static final long = 250` | кулдаун редстоуна на блок, мс |

## 4. Функциональные требования

### 4.1. Ограничение кликов по редстоун-блокам (`PlayerInteractEvent`)
- «Редстоун-блоком» считается: `Material.LEVER`, любой материал, имя которого
  содержит `BUTTON` или `DOOR`, `Material.REDSTONE_TORCH`, `Material.LECTERN`
  (метод `isRedstoneBlock`).
- При `Action.RIGHT_CLICK_BLOCK` по такому блоку: если с прошлого клика этого
  игрока прошло < 500 мс — событие отменяется (`setCancelled(true)`), клик «съедается».
- Иначе фиксируется время клика. Кулдаун общий на все редстоун-блоки (один таймер на игрока).

### 4.2. Гашение редстоуна и автобан (`BlockRedstoneEvent`, обработчик `onRedstoneTick`)
- Активен только когда `Bukkit.getTPS()[0] <= 12.0`.
- Каждое событие: счётчик локации `blocks[loc]` увеличивается на 1;
  `event.setNewCurrent(0)` — сигнал принудительно сбрасывается в 0
  (т.е. при TPS ≤ 12 вся редстоун-сеть фактически обесточивается).
- На 4-м событии и далее на каждом 16-м (`== 4 || % 16 == 0`):
  - перебираются игроки мира, расстояние от центра блока (`+0.5` по всем осям)
    до игрока ≤ 15.0 блоков;
  - каждому инкрементируется `players[p]`; при достижении счётчика ровно 2 —
    консоль выполняет `shame ban <ник>` (интеграция с плагином Shame).
- Т.е. бан срабатывает после второго «попадания» игрока в радиус подозрительного
  редстоуна; счётчик игрока далее не сбрасывается и повторно бан на том же значении
  не выполняется (условие строго `== 2`).

### 4.3. Рейт-лимитер редстоуна (`BlockRedstoneEvent`, обработчик `onRedstoneTick2`)
- Работает всегда (независимо от TPS), выполняется для каждого события после
  `onRedstoneTick`.
- Исключения: `Material.DISPENSER` и `Material.DROPPER` не ограничиваются.
- Если с прошлого изменения сигнала этого блока прошло < 250 мс —
  `event.setNewCurrent(0)` (сигнал гасится).

### 4.4. Команды и права
- Команд нет, права не проверяются и не объявлены (plugin.yml содержит только
  `name`, `version`, `main`, `api-version`).
- Консольная команда `shame ban` — исходящая, регистрируется не этим плагином.

### 4.5. Конфигурация и сообщения
- Отсутствуют: ресурсов, кроме plugin.yml, нет; config.yml не читается.
- Все параметры захардкожены: порог TPS 12.0, радиус 15.0, кулдауны 500/250 мс,
  пороги счётчиков 4/16 и 2, команда бана.

- Только оперативная память (HashMap). После перезапуска все счётчики и кулдауны
  сбрасываются. Файлов/БД нет.

## 7. Сценарий работы
1. Сервер работает нормально — активен только рейт-лимитер: редстоун-блок (кроме
   диспенсера/дроппера) меняет сигнал не чаще раза в 250 мс.
2. Игрок спамит кликами по рычагу/кнопке/двери/кафедре — клики чаще 500 мс отменяются.
3. Игрок строит и запускает редстоун-машину; TPS сервера проседает до ≤ 12.
4. Все редстоун-события начинают гаситься (`setNewCurrent(0)`), машина останавливается.
5. По каждому блоку считается число событий; на 4-м и каждом 16-м событии
   проверяются игроки в радиусе 15 блоков.
6. Игрок в зоне — счётчик `players` растёт; на втором попадании — `shame ban`.
7. Перезапуск плагина/сервера обнуляет все счётчики.

## 8. Особенности реализации и известные ограничения
- **Утечки памяти**: `blocks`, `players`, `lastUseTimes`, `lastRedstoneTimes` никогда
  не очищаются (нет eviction, нет очистки на quit/unload); `players` к тому же
  держит сильные ссылки на объекты `Player` после их выхода.
- **Хардкод**: все константы (TPS-порог, радиус, кулдауны, команда бана) в коде;
  настроить без пересборки нельзя.
- В `onPlayerInteract` сравнение `timeElapsed < 500L` использует литерал, а не
  константу `COOLDOWN` (значения дублируются).
- Бан по `== 2`: если игрок уже был замечен (счётчик > 2), повторное срабатывание
  для него невозможно, пока счётчик не сброшен перезапуском.
- Гашение сигнала при TPS ≤ 12 затрагивает **весь** редстоун сервера, а не только
  «машину» — законные механизмы тоже остановятся.
- `onRedstoneTick` и `onRedstoneTick2` — два независимых обработчика одного события,
  оба применяются одновременно.
- Нет `logger`-диагностики, нет уведомлений игрокам, нет exempt-права для админов.
- Возможен ложный бан игрока, просто стоящего рядом (≤ 15 блоков) с чужой машиной.
