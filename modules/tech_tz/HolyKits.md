# Техническое задание — модуль HolyKits

> Документ описывает фактическую реализацию модуля на основе анализа исходного кода
> (`modules/HolyKits`, ветка `mc-1.21.4`). Служит спецификацией для восстановления,
> доработки и поддержки плагина.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название плагина | HolyKits |
| Артефакт (Maven) | `HolyKits` (родитель `world.example:exampleworld-parent:1.0.0`) |
| Версия | 1.0 |
| Главный класс | `ru.nezxenka.holykits.HolyKits` |
| API-версия Bukkit | 1.16 |
| Авторы | nezxenka, Smail |
| Рантайм-библиотеки | `com.h2database:h2:1.4.200` (объявлена в plugin.yml `libraries`) |

**Назначение:** система игровых наборов (китов). Администраторы создают наборы,
снимая их со своего инвентаря (`/kitadmin setinv`), задают кулдаун и приоритет.
Игроки получают наборы командой `/kit <название>` с соблюдением прав доступа,
кулдаунов (хранятся в БД) и системы приоритетов (из доступных игроку наборов
разрешён только набор с максимальным приоритетом — донат-уровень). Новичку при
первом входе автоматически выдаётся стартовый набор `start`. Поддерживается
глобальное включение/отключение всех китов (на время или навсегда), выдача набора
другому игроку и команда-редирект `/kit shop` на меню DiscordModules.

---

## 2. Окружение и зависимости

### 2.1. Сервер
- Paper (используется `com.destroystokyo.paper.profile.PlayerProfile` в LegacySkullFix),
  API 1.16 (фактически код адаптирован под 1.21.4 — восстановление текстур голов).

### 2.2. Плагины
- DiscordModules (не объявлен в plugin.yml): `/kit shop` выполняет `dm open kitshop`.
- Другие зависимости (Vault, PAPI и т.п.) отсутствуют.

### 2.3. Библиотеки
- H2 1.4.200 — подключается через `libraries` в plugin.yml (загрузчик плагина
  скачивает из Maven Central). Используется как JDBC-драйвер в sqlite-режиме.
- MySQL-драйвер — берётся с сервера (в mysql-режиме).

---

## 3. Архитектура (структура пакетов)

```
ru.nezxenka.holykits
├── HolyKits                 — главный класс: создание папки, БД, менеджеры, команды
├── commands.KitCommand      — /kit (игрок: выдать себе; консоль/othergive: выдать другому)
├── commands.KitAdminCommand — /kitadmin (setinv/remove/settime/setpriority/
│                              clearcooldown/setenabled/give) + TabCompleter
├── commands.KitTabCompleter — TabComplete для /kit (названия наборов, shop, ники)
├── config.MessagesConfig    — messages.yml: сообщения о нехватке прав по наборам, HEX-цвета
├── database.Database        — JDBC (sqlite/mysql): кулдауны и глобальный статус наборов
├── listener.JoinKitListener — PlayerJoinEvent: стартовый набор новичку
├── managers.Kit             — модель набора: предметы по слотам, priority, cooldown, выдача
├── managers.KitManager      — реестр наборов, загрузка/сохранение config.yml, приоритеты
└── util.LegacyBlobReader    — сырой YAML-парсер `internal:`-блобов (текстуры голов 1.16.5)
└── util.LegacySkullFix      — восстановление текстур PLAYER_HEAD из legacy-NBT (gzip+Base64)
```

## 4. Функциональные требования

### 4.1. Команда `/kit` (usage из plugin.yml: `/kit <название>`)
| Вариант | Отправитель/право | Поведение |
|---|---|---|
| `/kit` (без аргументов) | игрок | Подсказка `§b▶ §fЧтобы получить набор, введите - §b/kit <название>` |
| `/kit shop` | игрок | `player.performCommand("dm open kitshop")` — открытие GUI кит-шопа |
| `/kit <набор>` | игрок | Основная выдача набора себе (см. ниже) |
| `/kit <набор> <игрок>` | игрок + `holykits.admin.othergive` | Выдача набора другому игроку (кулдаун списывается с отправителя) |
| `/kit <набор> <игрок>` | консоль | Выдача набора игроку без проверок прав/кулдауна |

Логика выдачи себе:
1. Проверка существования набора — иначе `§c▶ §fТакого набора §cне существует`.
2. Проверка глобального отключения (`isKitsDisabled`) — иначе сообщение
   `§x§F§D§1§A§0§B▶ §fИспользование §e/kit §x§F§D§1§A§0§Bотключено§f. Ограничение спадут через §x§1§D§C§2§F§F<время>`
   (время — из `kits_status.disabled_until`, «∞ (навсегда)» при 0; по истечении
   времени статус автоматически сбрасывается в БД).
3. Право `holykits.kit.<набор>` **или** `holykits.prioritybypass` — иначе сообщение
   из messages.yml (см. §5.2).
4. Приоритет: у `prioritybypass` — выдаётся запрошенный; иначе набор должен быть
   среди доступных игроку с максимальным приоритетом (`getBestPriorityKit`):
   запрашиваемый набор выдаётся только если его приоритет равен максимуму среди
   всех доступных игроку наборов (приоритет -1 — «вне конкурса», выдаётся всегда).
5. Кулдаун (если нет `holykits.bypass`): если `cooldown_end` из БД больше текущего
   времени — отказ с сообщением-блоком:
   ```
   (пустая строка)
          §b• §fДля повторного получения набора §6<набор>
               §fОсталось §b<дд дн. ЧЧ ч. ММ мин. СС сек.>
   (пустая строка)
   ```
   иначе при `cooldown > 0` в БД пишется `now + cooldown*1000` (кулдаун в секундах).
6. Выдача `Kit.applyToInventory` + `§b▶ §fВы получили набор §b<набор>`.

Формат оставшегося времени: `%d дн. %02d ч. %02d мин. %02d сек.` /
`%02d ч. %02d мин. %02d сек.` / `%02d мин. %02d сек.` / `%02d сек.`

### 4.2. Выдача набора (`Kit.applyToInventory`)
- Предметы ставятся в свои исходные слоты (0..40, включая броню/offhand), если слот пуст.
- Занятые слоты: предмет добаляется в инвентарь через собственный алгоритм
  (`addItemInventory`): сначала первый пустой слот, иначе досыпание в стопки
  однотипных предметов до maxStackSize.
- Если ничего не поместилось — дроп под ноги игрока (`runTask` + `dropItemNaturally`).

### 4.3. Стартовый набор (`JoinKitListener`, `PlayerJoinEvent`)
- Только если `!player.hasPlayedBefore()`.
- Набор с именем `start` (если существует и непустой) выдаётся в инвентарь;
  при `cooldown > 0` кулдаун также записывается в БД.

### 4.4. Команда `/kitadmin` (право `holykits.admin`, default op)
| Подкоманда | Синтаксис | Описание |
|---|---|---|
| `setinv` | `/kitadmin setinv <набор>` | Создать набор из инвентаря отправителя (слоты 0..40). Если набор существует — обновить его содержимое. В config.yml пишутся `priority`, `cooldown`, `items.<слот>` (ItemStack) |
| `remove` | `/kitadmin remove <набор>` | Удалить набор (секция из config.yml) |
| `settime` | `/kitadmin settime <набор> <секунды>` | Установить кулдаун (сек, long) |
| `setpriority` | `/kitadmin setpriority <набор> <приоритет>` | Установить приоритет (int; -1 = «вне конкурса») |
| `clearcooldown` | `/kitadmin clearcooldown <игрок> <набор>` | Сбросить кулдаун игрока (только онлайн-игрок) |
| `setenabled` | `/kitadmin setenabled <true/false> [время]` | Глобально вкл/выкл наборы. При `false <время>` — отключение на срок; время в формате `1h 30m` / `2d` / `12h` / `-1` (навсегда); суффиксы d/h/m/s складываются. `-1` = disabled_until = 0 (бесконечно) |
| `give` | `/kitadmin give <игрок> <набор>` | Выдать набор игроку без проверок прав/кулдауна (игроку приходит `§aВам выдали набор §b<набор>`) |

TabComplete: подкоманды; названия наборов (remove/settime/setpriority,
clearcooldown/give); ники онлайн (clearcooldown/give); `true/false` (setenabled);
для `setenabled false` — `1h 2h 3h 12h 24h 1d 2d 3d -1`.
Справка `/kitadmin` (без аргументов) — 6 строк `§6===== HolyKits Admin Help =====` и т.д.

### 4.5. Восстановление текстур голов (LegacySkullFix + LegacyBlobReader)
При загрузке наборов из config.yml:
1. `LegacyBlobReader` прямым парсингом YAML (по отступам, с учётом кавычек ключей
   и значений) собирает карту `<кит>.items.<слот> → base64-блоб internal:`
   (поле сериализации CraftBukkit 1.16.5 для PLAYER_HEAD; уровень `meta` из пути
   исключается).
2. `LegacySkullFix.repair(item, blob)`: если предмет — PLAYER_HEAD без текстур,
   блоб распаковывается (Base64 → GZIP → NBT-парсер, все теги 1–12), из
   `SkullProfile.Properties.textures[0].Value` берётся строка текстуры, из
   `Id` (int[4] или string) — UUID; профиль применяется через Paper
   `PlayerProfile`/`ProfileProperty("textures", value)`.
3. Файл на диске не изменяется; при还原 количество починенных голов логируется.
   Причина: 1.21.4 молча разбирает legacy-профиль в пустой (Steve/Alex).

### 4.6. Права
| Право | Default | Назначение |
|---|---|---|
| `holykits.admin` | op | Команда `/kitadmin` (в plugin.yml + код) |
| `holykits.bypass` | op | Взятие наборов без кулдауна |
| `holykits.kit.*` | op | Доступ ко всем наборам |
| `holykits.kit.<имя_набора>` | (не объявлено, по умолчанию false) | Доступ к конкретному набору |
| `holykits.prioritybypass` | (только в коде) | Выдача любого доступного набора без проверки максимального приоритета |
| `holykits.admin.othergive` | (только в коде) | `/kit <набор> <игрок>` — выдача другому |

### 4.7. Обрабатываемые события
- `PlayerJoinEvent` — стартовый набор новичку.

## 5. Конфигурация

### 5.1. `config.yml` (сами наборы; ресурс-шаблон пустой)
| Параметр | Тип | Default | Описание |
|---|---|---|---|
| `<набор>.priority` | int | `0` | Приоритет; -1 — «вне конкурса» (выдаётся всегда при праве) |
| `<набор>.cooldown` | long | `0` | Кулдаун набора, секунд |
| `<набор>.items.<слот>` | ItemStack | — | Предмет слота 0..40 (сериализация Bukkit; для PLAYER_HEAD — legacy `internal`-блоб) |

### 5.2. `messages.yml`
| Ключ | Описание |
|---|---|
| `default-no-permission` | Сообщение при нехватке права (default: `§c▶ §fУ вас нет прав на использование этого набора`) |
| `kit-permissions.<набор>` | Персональное сообщение о нехватке права для набора. В ресурсе заданы для `griefer`, `mustang`, `ghast`, `wither`, `kraken`, `dragon`, `stinger`, `eternity` — «Для получения доступа к данной команде требуется привилегия «...», о которой можно узнать в меню /priv» с HEX-градиентами `&#rrggbb` |

Цвета: `&#rrggbb` → `§x§r§r§g§g§b§b`, `&` → `§`.

### 5.3. `db.yml`
| Параметр | Тип | Default | Описание |
|---|---|---|---|
| `storage-type` | string | `"sqlite"` | `mysql` или `sqlite` |
| `mysql.host` / `port` / `database` | string/int | `localhost` / `3306` / `lite_kits` | Подключение MySQL |
| `mysql.username` / `password` | string | `plugins` / `kits` | Учётные данные |
| `mysql.useSSL` | boolean | `false` | Параметр JDBC |
| `sqlite.filename` | string | `kits.db` | Файл БД в папке плагина |

## 6. Хранение данных

### 6.1. `config.yml` — сами наборы (см. §5.1). Загрузка при старте, сохранение при изменении.

### 6.2. БД (JDBC, без пула, авто-реконнект `ensureConnection`)
| Таблица | Поля | Назначение |
|---|---|---|
| `kit_cooldowns` | `player_uuid VARCHAR(36), kit_name VARCHAR(32), cooldown_end BIGINT`, PK (player_uuid, kit_name) | Кулдауны игроков (epoch-millis окончания) |
| `kits_status` | `id INT (CHECK id=1), disabled BOOLEAN, disabled_until BIGINT` | Глобальный статус наборов (одна строка id=1; disabled_until — epoch-секунд, 0 = навсегда) |

- MySQL: `INSERT ... ON DUPLICATE KEY UPDATE`; SQLite: `INSERT OR REPLACE`;
  `INSERT IGNORE`/`INSERT OR IGNORE` для сид-строки kits_status.
- Остальные тексты и перечень наборов в БД не хранятся.

## 8. Сценарий работы
1. Админ: `/kitadmin setinv start` с инвентарём, полным стартовых предметов;
   `/kitadmin settime start 86400`; `/kitadmin setpriority <донат-набор> N`.
2. Новый игрок заходит — набор `start` автоматически в инвентаре, кулдаун стартует.
3. Игрок вводит `/kit <набор>` → проверки: отключены ли наборы глобально, право,
   максимальный приоритет, кулдаун → выдача предметов в исходные слоты, остаток —
   в свободные слоты/стопки, излишек — дроп под ноги.
4. Админ может временно выключить наборы `/kitadmin setenabled false 12h` —
   игроки получают сообщение с остатком времени; по истечении статус
   сбрасывается автоматически при следующей проверке.
5. При загрузке наборов текстуры голов, сериализованных на 1.16.5, восстанавливаются
   из legacy-NBT без изменения файла.

## 9. Особенности реализации и известные ограничения
- Наборы определяются правом `holykits.kit.<имя>`; права не создаются автоматически —
  выдаются пермишен-плагином согласно донат-уровням (сообщения messages.yml
  соответствуют привилегиям griefer..eternity).
- Логика приоритетов: игрок может взять только набор с максимальным приоритетом
  среди доступных ему; т.е. старший донат «прячет» младшие наборы с меньшим
  приоритетом. `-1` — исключение из конкуренции.
- БД — синхронный JDBC в главном потоке (без пула/асинхронности); при недоступности
  БД плагин отключается на старте.
- `armor`-секция создаётся пустой при сохранении набора (зарезервировано, не читается).
- `KitCommand` с консоли требует 2 аргумента; с одним аргументом — «только для игроков».
- Секция `database:` в ресурсе config.yml пустая — реальная конфигурация БД в db.yml.
- H2 объявлена в plugin.yml `libraries` — при сборке вне сети сервер должен иметь
  доступ к Maven Central (или библиотеку в кэше).
- Восстановление черепов — «костыль» миграции 1.16.5 → 1.21.4: работает на лету,
  файл не переписывается; повторная сериализация конфига запишет уже новый формат.

## 10. Сборка
```
mvn -pl HolyKits package     # из каталога modules
```
Внешних зависимостей в pom нет (пустой `<dependencies>`); Paper API и H2
подхватываются в рантайме.
